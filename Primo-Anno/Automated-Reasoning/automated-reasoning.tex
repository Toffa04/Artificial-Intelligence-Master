\section{Introduction}
\subsection{Why study Automated Reasoning?}
Automated Reasoning is a foundamental field of Artificial Intelligence concerned with the design
and implementation of computionals procedures that enable machines to solve problems formulated in logical
languages. This procedures involve \textbf{logical inference and search}, allowing system to reason
in a deductive manner throught mechanical process.
\vspace{1em}
\noindent
\newline
Since the inception of Artificial intelligence at the Dartmouth Conference in 1956, one of the core challenges
has been to demonstrate machine intelligence throught the automated proving of mathematical and logical theorems.
This capability represents a cornerstone of symbolic AI, where knowledge is rapresented symbolically and 
stored in computer memory, and systematic procedures are applied to solve complex problems.

\begin{theorem}{Theorem Proving}{Theorem Proving}
    Traditionally require human-level mathematical reasoning and insight. The goal of automated 
    reasoning is to mecanize this process, creating algorithms and systems capable of performing 
    logical deduction without human intervention.
\end{theorem}
\noindent
A logical language consist of formal symbols and syntactic rules. Within the symbolic approach to 
artificial intelligence, knowledge is encoded using these symbols, which are stored in computer memory.
The system then applies a sequence of mechanical steps to manipulate these symbols and arrive at solutions
to given problems.
\section{Historical Foundations and Theoretical Limits}
\subsection{The Hilbert-Turing Perspective}
The foundations of automated reasoning can be traced to fundamental questions in mathematical
logic and computability. Since Alan Turing's seminal work on Turing machines in 1936, researchers have
pursued David Hilbert's 1900 challenge: is it possible to develop a mechanical
procedure-executed deterministically by human computor-capable of solving any mathematical problem?
\vspace{1em}
\noindent 
\newline
\textbf{The Entscheidungsproblem}: A central question that emerged from this pursuit asks whether it is 
possible to define a mechanical method to detrmine the validity of formulas in first-order logic.
\vspace{1em}
\noindent 
\newline
Turing demostrated that the halting problem is undecidable using Turing machines. This fundamental result can be reduced to the validity
problem in first-order logic, providing a negative answer to Hilbert's challenge. This undecidability result forms one of the core theoretical
foundations of automated reasoning, estabilishing fundamental limits on what can be mechanically computed.

\subsection{Practical Applications of Automated Reasoning}
Automated reasoning find application across multiple domains requiring formal verification and systematic problem-solving:
\begin{itemize}
	\item \textbf{Planning}: Given an initial state, goal state, and formal model of agent actions, determine a sequence of moves that transforms the initial state into the goal state (utilizing SAT solvers)
	\item \textbf{Scheduling}: Generate temporal arrangements of tasks that stisfy complex temporal and resource constraints 
	\item \textbf{Software Analysis and Verfication}: Formal methods for ensuring program correctenss, including:
	\begin{itemize}
		\item Provable privacy guarantees in security protocols 
		\item Verification of distributed algorithms
		\item Analysis of randomized algorithms and their probabilistic properties
	\end{itemize}
	\item \textbf{Hybrid Approaches}: Integration of automated reasoning with machine learning techniques for enhanced problem-solving capabilities
\end{itemize}
These applications demonstrate the practical utility of automated reasoning in solving complex real-world problems that require rigouros logical 
analysis and systematic exploration of solution spaces.
\section{Core Problems in Automated Reasoning}
Automated reasoning fundamentally addresses three interconnected classes of decision problems in mathematical logic, each representing a distinct 
challenge in determining the truth properties of logical formulas.
\[
	\underline{\textbf{The Three Core Problems in Automated Reasoning}}
\]
\begin{enumerate}
	\item \textbf{Satisfiability (SAT)}: Does there exist a model?
	\item \textbf{Validity}: Is the formula true in all models?
	\item \textbf{Logical Consequence}: Does the conclusion follow from premises?
\end{enumerate}
\subsection{Satisfiability problems}
A satisfiability problem (SAT) concerns determining whether a given logical formula has a truth assignment that makes it true. Formally,
for a formula \( \phi \) with free variables, we seek to determine if there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models \phi \). This 
represent the existence problem - does there exists a model making the formula true?
\subsection{Validity problems}
In contrast to satisfiability, validity problems ask whether a formula holds true under all possible interpretations.
A formula \( \phi \) is valid (denoted \( \models \phi \)) if every possible truth assignment to its variables result in 
\( \phi \) evaluating to true. This correspond to the unversal quantification over all possible models - the formula must 
hold in every conceivable scenario.
\subsection{Logical Consequence Problems}
The logical consequence problem represents a generalization of validity, asking whether a conclusion necessarly follows from 
given permises. Given a set of assumptions \( \varGamma = \left\{ \phi_1, \phi_2, \ldots, \phi_n \right\} \) and a conjecture 
\( \psi \), we determine if \( \varGamma \models \psi \) (i.e., if \( \psi \) is true in every model where all formulas 
in \( \varGamma \) are true). This captures the essence of logical deduction - what conclusions are forced by the given information.
\vspace{1em}
\noindent 
\newline
These three problems form the foundation of automated reasoning systems, with satisfiability 
serving as the most tractable and finding widespread application in pratical problem-solving contexts.
\section{Formal Language and Semantics}
\subsection{Logical Language: First-Order Logic}
The formal language employed in automated reasoning is first-order logic (FOL), a substantial extension of propositional logic
that incorporates quantification over individual elements.
\[
  \underline{\textit{First-Order Logic Components}}
\] 
\textit{First-order logic achieves greater expressive power by introducting}:
\begin{itemize}
	\item \textit{Individual variables} ranging over domain elements
	\item \textit{Function symbols} for constructing complex terms 
	\item \textit{Predicate symbols} for expressing relations between elements 
	\item \textit{Quantifiers} \( \forall, \exists \) enabling statements about all or some elements
\end{itemize}
This enhanced expressiveness allows first-order logic to formalize mathematical structures, relationship, and properties 
in a manner impossible in propositional logic, which can only express truth-functional combinations of atomic propositions 
\subsection{Signature and Universe of Discourse}
A signature \( \Sigma \) provied the vocabulary for interpreting formulas within a specific domain. Formally, a signature is 
a triple \( \Sigma = \langle \mathcal{S}, \mathcal{F}, \mathcal{P} \rangle \) where:
\begin{itemize}
	\item \( \mathcal{S} \) is a set of sorts (disjoint domains of interpretation)
	\item \( \mathcal{F} \) is a set of function symbols, each with an arity specifying the number of arguments 
	\item \( \mathcal{P} \) is a set of predicate symbols, which we use to write formulas, each with an associated arity 
\end{itemize}
The signature defines the syntactic elements available for constructing formulas, while the universe of discourse (or domain) provides 
the semantic interpretation. Sorts correspond to types in programming languages, enabling the formal specification of heterogeneous 
domains with different categories of objects.
\vspace{1em}
\noindent
\newline
The signature \( \Sigma = \langle \mathcal{S}, \mathcal{F}, \mathcal{P} \rangle \) cna be further decomposed to provide a complete syntactic 
framework. The set of function symbols \( \mathcal{F} \) is typically partitioned into two distinct subset:
\begin{itemize}
	\item \textbf{Constant symbols} \( \mathcal{C} \subseteq \mathcal{F} \): These are function symbols of arity 0, representing 
		named individuals in the domain. Constants have fixed interpretations and serve as proper names for specific domain elements 
	\item \textbf{Proper function symbols} \( \mathcal{F} \setminus \mathcal{C} \): These represent actual functions mapping tuples 
		of domain elements to domain elements, each with arity \( n \geq 1 \).
\end{itemize}
Formally, a function symbol \( f \in \mathcal{F} \) has type \( s_1 \times s_2 \times \ldots \times s_n \rightarrow s \), where 
\( s_1, \ldots, s_n, s \in \mathcal{S} \) are sorts indicating the domain and codomain of the function. For example:
\begin{itemize}
	\item \( c :\rightarrow \texttt{int} \) (a costant symbol denoting a specific integer)
	\item \( p :\rightarrow \texttt{color} \) (a costant symbol denoting a specific color)
	\item \( f : \texttt{int} \rightarrow \texttt{int} \) (a binary function like addition)
\end{itemize}
This decomposition enables precise specification of both individual elements (via constants) and functional relationships 
(via proper function symbol) within the formal language.
\vspace{1em}
\noindent
\newline
This complete signature structure \( \langle \mathcal{S}, \mathcal{C} \cup (\mathcal{F} \setminus \mathcal{C}) \cup \mathcal{P} \rangle \) provides 
the full syntactic foundation for expressing complex logical statements about structured domains.
\vspace{1em}
\noindent
\newline
Constant can be viewed as function symbols of arity - functions that require no arguments and directly denote specific domain elements.
Additionally, to construct quantified formulas and express generality, we require a countably infinte set of variables \( X = \left\{x,y,z,\ldots \right\} \) disjoint
from the signature symbols.
\vspace{1em}
\noindent
\newline
Thus, the function symbols may be comprehensively categorized as \( \mathcal{F} = \mathcal{C} \cup ( \mathcal{F} \setminus \mathcal{C}) \cup \mathcal{P} \), where 
\( \mathcal{P} \) represents the set of predicate symbols. Each predicate symbol \( p \in \mathcal{P} \) has arity \( n \geq 0 \) and 
type \( s_1 \times s_2 \times \ldots \times s_n \), where the final sort represents the truth value (typically a boolean sort).
\vspace{1em}
\noindent
\newline
Predicate symbols differ fundamentally from function symbols in that they represent relations 
rather than functions - they evaluate to truth values rather than domain elements. For example:
\begin{itemize}
	\item \textit{even}: \( \texttt{int} \rightarrow \texttt{bool} \) (unary predicate testing parity)
	\item \textit{less}: \( \texttt{int} \times \texttt{int} \rightarrow \texttt{bool} \) (binary relation for ordering)
\end{itemize}
The complete singature structure \( \langle \mathcal{S}, \mathcal{C} \cup (\mathcal{F} \setminus \mathcal{C}) \cup \mathcal{P} \rangle \) provides the full syntactic foundation for expressing 
complex logical statements about structured domains.
\vspace{1em}
\noindent
\newline
Constants can be viewed as function symbols of arity 0 - functions that require no arguments and directly denote 
specific domain elements. Additionally, to construct quantified formulas and express generality, we require a countably 
infinite set of variables \( X = \left\{ x,y,z, \ldots \right\} \) disjoint from the signature symbols.

\section{Syntactic Foundations: Terms and Formulas}
\subsubsection{Terms: The building blocks}
The most foundamental syntactic objects in first-order logic are \textbf{terms}, which represent individuals in the 
domain of discourse. The set of terms \( \mathcal{T}_{\Sigma} (\mathcal{X}) \) over signature \( \Sigma \) and variables \( \mathcal{X} \) is 
inductively defined as the smallest set satisying:
\begin{itemize}
	\item \textbf{Constants}: If \( c \in \mathcal{C} \) is a constant symbol, then \( c \in \mathcal{T}_{\Sigma} (\mathcal{X}) \).
	\item \textbf{Variables}: If \( x \in \mathcal{X} \) is a variable, then \( x \in \mathcal{T}_{\Sigma} (\mathcal{X}) \).
	\item \textbf{Function application}: If \( f \in \mathcal{F} \) is a function symbol of arity \( n \geq 1 \) and \( t_1, \ldots, t_n \in \mathcal{T}_{\Sigma} (\mathcal{X}) \) are terms, then \( f(t_1,\ldots,t_n) \in \mathcal{T}_{\Sigma} (\mathcal{X}) \).
\end{itemize}
Terms can be conceptualized as finite trees where: 
\begin{itemize}
	\item Leaf nodes are constants or variables 
	\item Internal nodes are function symbols applied to subterms
\end{itemize}
For example, the term \( f(x,g(a),z) \) has the tree representation:
\begin{center}
	\begin{tikzpicture}[node distance = 0.9cm]
		\node (f) at (0,1.6) {$f$};
		\node (x) at (-1,0.8) {$x$};
		\node (g) at (0,0.8) {$g$};
		\node (z) at (1,0.8) {$z$};
		\node (a) at (0,0) {$a$};

		\draw[blue] (f.south) -- (g.north);
		\draw[purple] (g.south) -- (a.north);
	\end{tikzpicture}
\end{center}
Terms may contain subterms, which correspond to subtrees in this representation. Complex terms are constructed 
recursively from simpler subterms, reflecting the hierarchical nature of the syntactic structure.
\subsubsection{From terms to Atomic Formulas}
Having established the notion of terms as representations of individuals, we now introduce atomic 
formulas to express relationships between these individuals. An \textbf{atomic formula} (or \textbf{atom}) is 
constructed by applying a predicate symbol to an appropriate number of terms.
\vspace{1em}
\noindent
\newline
Formally, if \( P \in \mathcal{P} \) is a predicate symbol of arity \( n \geq 0 \) and \( t_1, \ldots, t_n \in \mathcal{T}_{\Sigma} (\mathcal{X}) \) are terms,
then \( P(t_1,\ldots,t_n) \) is an atomic formula. When \( n = 0 \), the atomic formula reduces to the predicate 
symbol itself \( P \), which can be interpreted as a propositional constant.
\vspace{1em}
\noindent
\newline
The truth value of an atomic formula \( P(t_1,\ldots,t_n) \) depends on the interpretation of the predicate 
\( P \) and the denotations of the terms \( t_1,\ldots,t_n \) in a given model.
\subsection{Literals: Positive and Negative Atomic Formulas}
A \textbf{literal} is either an atomic formula (positive literal) or its negation (negative literal).
Formally, if \( \phi \) is an atomic formula, then:
\begin{itemize}
	\item \( \phi \) is a positive literal 
	\item \( \lnot \phi \) is a negative literal
\end{itemize}
Literals represent the basic building blocks for constructing complex logical formulas 
and play a crucial role in automated reasoning system, particularly in resolution-based theorem proving.
\subsection{Logical Connectives}
Logical connectives provide the means to construct complex formulas simpler ones. These operators
enable the expression of compound logical statements through systematic combination of atomic formulas and literals.
\vspace{1em}
\noindent
\newline
The primary logical connectives include:
\begin{itemize}
	\item \textbf{Negation}(\( \lnot \)): Express logical denial or contradiction 
	\item \textbf{Conjunction}(\( \wedge\)): Represents logical conjunction (AND) 
	\item \textbf{Disjunction}(\( \vee \)): Represent logical disjunction (OR)
	\item \textbf{Implication}(\( \rightarrow \)): Expresses logical implication (IF...THEN)
	\item \textbf{Biconditional}(\( \leftrightarrow \)): Represent logical equivalence (IF AND ONLY IF) 
\end{itemize}
\subsection{Formulas: The Complete Syntax}
The set of \textbf{formulas} (or \textbf{well-formed formulas}) \( \mathcal{F}_{\Sigma} (\mathcal{X}) \) over signature \( \Sigma \) and variables \( \mathcal{X} \) is 
inductively defined as the smallest set satisying:
\begin{itemize}
	\item \textbf{Atomic formulas}: If \( P \in \mathcal{P} \) is a predicate symbol of arity \( n \geq 0 \) and \( t_1, \ldots, t_n \in \mathcal{F}_{\Sigma} (\mathcal{X}) \), then \( P(t_1, \ldots, t_n) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \).
	\item \textbf{Negation}: If \( \phi \in \mathcal{F}_{\Sigma} (\mathcal{X}) \), then \( (\lnot \phi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \). 
	\item \textbf{Binary connectives}: If \( \phi, \psi \in \mathcal{F}_{\Sigma} (\mathcal{X}) \), then:
	\begin{itemize}
		\item \( (\phi \wedge \psi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \) (conjunction)
		\item \( (\phi \vee \psi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \) (disjunction)
		\item \( (\phi \rightarrow \psi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \) (implication)
		\item \( (\phi \leftrightarrow \psi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \) (biconditional)
	\end{itemize}
\end{itemize}
This inductive definition ensures that all syntactically valid logical expressions can be systematically constructed 
from the basic building blocks of atomic formulas through the application 
of logical connectives.
\subsection{Quantifiers: Universality and Existence}
To complete the syntax of first-order logic, we introduce quantifiers that express generality 
and existence over the domain of discourse:
\begin{itemize}
	\item \textbf{Universal quantifier} \( (\forall) \): If \( \phi \in \mathcal{F}_{\Sigma} (\mathcal{X}) \) is a formula and \( x \in \mathcal{X} \) is a variable, then 
		\( (\forall x \phi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \).
	\item \textbf{Existential quantifier} \( (\exists) \): If \( \phi \in \mathcal{F}_{\Sigma} (\mathcal{X}) \) is a formula and \( x \in \mathcal{X} \) is a variable, then 
		\( (\exists x \phi) \in \mathcal{F}_{\Sigma} (\mathcal{X}) \)
\end{itemize}
Quantifiers bind variables within thei scope, enabling the expression of properties that hold 
for all elements of the domain (universal quantification) or for at least one element (existential quantification).
\subsection{Illustrative Example: Geometric Axioms}
Consider the following first-order formula expressing that any two distinct points determine a unique line:
\[
  \forall x \forall y ((P(x) \wedge P(y) \wedge x \neq y) \rightarrow \exists z (L(z) \wedge Q(z,x,y) \wedge \forall w (L(w) \wedge Q(w,x,y) \rightarrow w = z)))
\]
Where:
\begin{itemize}
	\item P(x) denotes that \( x \) is a point 
	\item L(z) denotes that \( z \) is a line 
	\item Q(z,x,y) denotes that line z passes through points and \( x \) and \( y \).
	\item \( x \neq y \) expresses that points \( x \) and \( y \) are distinct
\end{itemize}
The axioms formalizes the geometric principle that given any two distinct points in space, there 
exists exactly one line passing through both points, capturing a foundamental property of Euclidean geometry within the 
framework of first-order logic.
\subsection{Closed Formulas and Variable Scope}
A \textbf{closed formula} (or \textbf{sentence}) is a formula containing no free variables - all variables are bound by 
quantifiers. A variable is \textbf{free} ina a formula if it appears outside the scope of any 
quantifier that binds it; conversely, a variable is \textbf{bound} if it appears within the scope of a quantifier.
\vspace{1em}
\noindent
\newline
Formulas may contain both free and bound occurences of variables. For proper semantica interpretation, variables must be
\textbf{standardized apart}, meaning that no variable appears both free and bound 
in the same formula, and distinct quantifiers use distinct bound variables.
\part{Semantic Foundations}
\section{Interpretations and Model}
\subsection{The concept of Interpretation}
To assign meaning to syntactic formulas in first-order logic, we require a formal notion of 
\textbf{interpretation}. An interpretation \( \mathcal{I} \) provides a semantic mapping from the syntactic elements 
of a signature to concrete mathematical objects.
\begin{definition}{Interpretation Components}{Interpretation Components}
In the unsorted case, an interpretation consists of:
\begin{itemize}
	\item A non-empty set D called the \textbf{domain} (or universe of discourse)
	\item An interpretation function \( \Phi \) that maps:
	\begin{itemize}
		\item Each predicate symbol \( P \in \mathcal{P} \) of arity \( n \) to a subset \( \Phi(P) \subseteq D^n \) (representing an \( n \)-ary realtion over the domain)
		\item Each function symbol \( f \in \mathcal{F} \) of arity \( n \) to a function \( \Phi(f) : D^n \rightarrow D \).
		\item Each constants symbol \( c \in \mathcal{C} \) to a specific element \( \Phi(c) \in D \).
 	\end{itemize}
\end{itemize}
\end{definition}
The interpretation function \( \Phi \) bridges the gap between syntax and semantics, transforming abstract symbols into concrete 
mathematical entities.
\subsection{Example: Interpreting a Formula over Natural Numbers}
Consider the first-order formula:
\[
  \forall x (\lnot P(x) \rightarrow P(f(x)))
\]
The formula contains:
\begin{itemize}
	\item A unary predicate symbol \( P \) 
	\item A unary function symbol \( f \)
	\item A universally quantified variable \( x \)
\end{itemize}
Since the formula is closed (contains no free variables), its truth value depends entirely on the chosen interpretation.
\vspace{1em}
\noindent
\newline
\textbf{Constructing an interpretation}: Let us define an interpretation \( \mathcal{I} = \langle D, \Phi \rangle \) where:
\begin{itemize}
	\item \textbf{Domain}: \( D = \mathbb{N} \) (the set of natural numbers)
	\item \textbf{Function interpretation}: \( \Phi(f) : \mathbb{N} \rightarrow \mathbb{N} \) is the successor function, defined by \( \Phi(f)(n) = n + 1 \) for all \( n \in \mathbb{N} \).
	\item \textbf{Predicate interpretation}: \( \Phi(P) = \left\{0,2,4,6,\ldots \right\} = \left\{ 2k \;|\; k \in \mathbb{N} \right\} \) (the set of even natural numbers)
\end{itemize}
\subsection{Semantic Evaluation}
Under this interpretation \( \mathcal{I} \), the formula \( \forall x (\lnot P(x) \rightarrow P(f(x))) \) receives the following 
semantic reading:
\vspace{1em}
\noindent
\newline
\textit{For all natural numbers x, if x is not even, then the successor of x is even}.
\vspace{1em}
\noindent
\newline
To determine whether this formula is true in interpretation \( \mathcal{I} \) we must verify whether the implication holds for every element of the domain:
\begin{itemize}
	\item If \( x \) is odd (i.e., \( x \notin \Phi(P)) \), then \( x + 1 \) must be even (i.e., \( x + 1 \in \Phi(P)) \)
\end{itemize}
The statement is indeed true in the natural numbers: the successor of any odd number is even.
Therefore, the formula is \textbf{satisfied} by interpretation \( \mathcal{I} \), and we write \( \mathcal{I} \models \forall x(\lnot P(x) \rightarrow P(f(x))) \).
\subsection{Formal Verification of Satisfaction}
The formally verify that \( \mathcal{I} \models \forall x (\lnot P(x) \rightarrow P(f(x))) \), we must check that for all \( n \in \mathbb{N} \), the 
interpretation satisfies the implication with the substitution \( \left\{ x \leftarrow n \right\} \).
\vspace{1em}
\noindent
\newline
By the semantics of implications, \( \mathcal{I} \) satisfies \( (\lnot P(x) \rightarrow P(f(x))) \) with assignment \( \left\{ x \leftarrow n \right\} \) if and only if:
\begin{itemize}
	\item Either \( \mathcal{I} \) does not satisfy \( \lnot P(x) \) with \( \left\{ x \leftarrow n \right\} \) (i.e., \( \mathcal{I} \) satisfies \( P(x) \) with \( \left\{ x \leftarrow n \right\} \)), or 
	\item \( \mathcal{I} \) satisfies \( P(f(x)) \) with \( \left\{ x \leftarrow n \right\} \)
\end{itemize}
Equivalently, for all \( n \in \mathbb{N} \), either \( n \in \Phi(P) \) or \( \Phi(f)(n) \in \Phi(P) \).
\vspace{1em}
\noindent
\newline 
\textbf{Truth condition for atomic formulas}: An atomic formula \( P(t) \) is true under interpretation 
\( \mathcal{I} \) if and only if the interpretation of the term \( t \) belongs to the interpretation of the predicate \( \Phi(P) \)..
\vspace{1em}
\noindent
\newline 
In our example, for all \( n \in \mathbb{N} \):
\begin{itemize}
	\item Either \( n \in \Phi(P) \) (meaning \( n \) is even), or 
	\item \( \Phi(f)(n) = n + 1 \in \Phi(P) \) (meaning the successor of \( n \) is even)
\end{itemize}
This condition holds for all natural numbers, confirming that the formula is satisfied by the interpretation.
\subsection{Formal Definition of Interpretation}
Having illustrated the concept through examples, we now provide the complete formal definition 
of an interpretation in first-order logic.
\vspace{1em}
\noindent
\newline
An \textbf{interpretation} \( \mathcal{I} \) consists of a triple \( \mathcal{I} = \langle D, \Phi, \beta \rangle \) where:
\begin{itemize}
	\item \textbf{Domain}: \( D \) is a non-empty set representing the universe of discourse 
	\item \textbf{Interpretation function} \( \Phi \) maps signature symbols to semantic objects:
	\begin{itemize}
		\item For each constant symbol \( c \in \mathcal{C}: \Phi(c) = d \in D \).
		\item For each function symbol \( f \in \mathcal{F} \) of arity \( n \geq 1: \Phi(f) : D^n \rightarrow D \), where \( D^n \) denotes the \( n \)-fold Cartesian product \( D \times D \times \ldots \times D \).
		\item For each predicate symbol \( P \in \mathcal{P} \) of arity \( n \geq 0: \Phi(P) \subseteq D^n \) (an \( n \)-ary relation over \( D \)) 		
	\end{itemize}
	\item \textbf{Variable assignment} \( \beta \) maps each variable to a domain element:
	\begin{itemize}
		\item \( \beta : \mathcal{X} \rightarrow D \) such that \( \beta(x) = d \in D \) for all variables \( x \in \mathcal{X} \)
	\end{itemize}
\end{itemize}
\textbf{Assignement update notation}: Given an assignment \( \beta \) and a substitution \( x \leftarrow d \), we define 
the updated assignment \( \beta[x \leftarrow d] \) as:
\[
  \beta[x \leftarrow d](y) = \begin{cases}
	d & \text{if } y = x \\
	\beta(y) & \text{otherwise}
  \end{cases}
\]
This notation allows us to formally express the evaluation of formulas with different variable bindings, 
which is essential for defining the semantics of quantified formulas.
\section{Satisfaction Relation}
\subsection{The satisfaction relation}
Having defined interpretations and variable assignments, we now formalize the central semantica concept: when 
does an interpretation \textbf{satisfy} a formula? The satisfaction relation, denoted 
\( \mathcal{I} \models_{\beta} \Phi \), specifies the conditions under which a formula \( \Phi \) is true in interpretation \( \mathcal{I} \) with 
variable assignment \( \beta \).
\vspace{1em}
\noindent
\newline
Let \( F \) and \( G \) denote arbitraty formulas. The satisfaction realtion is defined inductively on the 
structure or formulas.
\subsection{Interpretation of Terms}
Before defining satisfaction for formulas, we must specify how terms are interpreted. Given an interpretation \( \mathcal{I} = \langle D, \Phi, \beta \rangle \),
the interpretation of a term \( t \), denoted \( \Phi_{\beta}(t) \), is defined recursively:
\begin{itemize}
	\item \textbf{Constants}: \( \Phi_{\beta}(c) = \Phi(c) \in D \) 
	\item \textbf{Variables}: \( \Phi_{\beta}(x) = \beta(x) \in D \)   
	\item \textbf{Function application}: \( \Phi_{\beta}(f(t_1, \ldots, t_n)) = \Phi(f)(\Phi(t_1), \ldots, \Phi_{\beta}(t_n)) \in D \) 
\end{itemize}
Each term evalueates to a specific element of the domain under a given interpretation.
\subsection{Satisfaction for Atomic Formulas}
\textbf{Base case} (atomic formulas): An interpretation \( \mathcal{I} \) satisfies an atomic formula \( P(t_1,\ldots, t_n) \) under 
assignment \( \beta \) if and only if the tuple of interpreted terms belongs to the interpretation of the predicate:
\[
  \mathcal{I} \models_{\beta} P(t_1,\ldots,t_n) \text{ iff } (\Phi_{\beta}(t_1), \ldots, \Phi_{\beta}(t_n)) \in \Phi(P)
\]
\subsection{Satisfaction for Logical Connectives}
The satisfaction relation extends to compound fomrulas through the following inductive clauses. Note that all satisfaction relations 
are parametrized by the variable assignment \( \beta \), written as \( \models_{\beta} \)
\begin{itemize}
	\item \textbf{Negation}:
	\[
	  \mathcal{I} \models_{\beta} \lnot F \text{ iff } \mathcal{I} \nvDash_{\beta} F 
	\]
	\item \textbf{Conjunction}: 
	\[
	  \mathcal{I} \models_{\beta} (F \wedge G) \text{ iff } \mathcal{I} \models_{\beta} F \text{ and } \mathcal{I} \models_{\beta} G
	\]
	\item \textbf{Disjunction}:
	\[
	  \mathcal{I} \models_{\beta} (F \vee G) \text{ iff } \mathcal{I} \models_{\beta} F \text{ or } \mathcal{I} \models_{\beta} G
	\]
	\item \textbf{Implication}:
	\[
	  \mathcal{I} \models_{\beta} (F \rightarrow G) \text{ iff } \mathcal{I} \nvDash_{\beta} F \text{ or } \mathcal{I} \models_{\beta} G 
	\]
	Equivalently: if \( \mathcal{I} \models_{\beta} F \) then \( \mathcal{I} \models_{\beta} G \).
	\item \textbf{Biconditional}:
	\[
	  \mathcal{I} \models_{\beta} (F \leftrightarrow G) \text{ iff } \mathcal{I} \models_{\beta} F \text{ if and only if } \mathcal{I} \models_{\beta} G
	\]
	The formula \( \exists x G \) is satisfied if \( G \) is satisfied under at least one assignment to \( x \).
\end{itemize}
This completes the inductive definition of the satisfaction relation, providing a complete semantics for first-order logic.
\subsection{Example: Quantifier Evaluation}
Consider the formula \( \forall x \exists y R(x,y) \), which can be read as "for all \( x \), there exists \( y \) such that 
\( x < y \)".
\vspace{1em}
\noindent
\newline
Let \( \mathcal{I} = \langle \mathbb{N}, \Phi \rangle \) where \( \Phi(R) = \left\{ (n,m) \in \mathbb{N} \times \mathbb{N} \;|\; n < m \right\} \) (the 
standard ordering on natural numbers).
\vspace{1em}
\noindent
\newline
To verify \( \mathcal{I} \models \forall x \exists y R(x,y) \), we apply the semantic definitions:
\begin{align*}
	& \mathcal{I} \models \forall x\, \exists y\, R(x,y) \\
	\iff\ & \text{per ogni } n \in \mathbb{N},\
		\mathcal{I} \models_{\beta[x \leftarrow n]} \exists y\, R(x,y) \\
	\iff\ & \text{per ogni } n \in \mathbb{N},\ \text{esiste } m \in \mathbb{N} \text{ tale che }
		\mathcal{I} \models_{\beta[x \leftarrow n,\, y \leftarrow m]} R(x,y) \\
	\iff\ & \text{per ogni } n \in \mathbb{N},\ \text{esiste } m \in \mathbb{N} \text{ tale che }
		(n,m) \in \Phi(R) \\
	\iff\ & \text{per ogni } n \in \mathbb{N},\ \text{esiste } m \in \mathbb{N} \text{ tale che }
		n < m
\end{align*}
This statement is \textbf{false} in \( \mathbb{N} \) because there is no natural number greater than all natural numbers.
However, it would be true \( \mathbb{Z} \) or \( \mathbb{Q} \), demonstrating how truth depends on the chosen interpretaion.
\section{Semantic Properties of Formulas}
Having established the satisfaction relation, we now define fundamental semantic properties that classify formulas according 
to their to their truth behavior across different interpretations.
\begin{definition}{Semantic Properties of Formulas}{Semantic Properties of Formulas}
\textbf{Satisfiability}
\newline
A formula \( F \) is \textbf{satisfiable} if there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models F \).
\[
  F \text{ is satisfiable } \Leftrightarrow \exists \mathcal{I} : \mathcal{I} \models F
\]	
\textbf{Validity}
\newline
A formula \( F \) is \textbf{valid} (or a \textbf{tautology}) if for all interpretations \( \mathcal{I} \), we have \( \mathcal{I} \models F \).
\[
  F \text{ is valid } \Leftrightarrow \forall \mathcal{I} : \mathcal{I} \models F 
\]
\textbf{Unsatisfiability}
\newline
A formula \( F \) is \textbf{unsatisfiable} if there exists no interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models F \).
\[
  F \text{ is unsatisfiable } \Leftrightarrow \nexists \mathcal{I} : \mathcal{I} \models F  
\]
\textbf{Invalidaity}
\newline
A formula \( F \) is \textbf{invalid} if there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \nvDash F \).
\[
  F \text{ is invalid } \Leftrightarrow \exists \mathcal{I} : \mathcal{I} \nvDash F
\]
\end{definition}
\subsection{Satisfiability}
A formula \( F \) is \textbf{satisfiable} if there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models F \). In thi case, 
we say that \( \mathcal{I} \) is a \textbf{model} of \( F \).
\subsection{Validity}
We denote validity by \( \models F \).
\subsection{Unsatisfiability}
Unsatisfiable formulas are false in every interpretation.
\subsection{Invalidity}
In this case, we say that \( \mathcal{I} \) is a \textbf{countermodel} (or \textbf{counterexample}) for \( F \).
\subsection{Relationship Between Semantic Properties}
These semantic properties are intimately related through negation:
\begin{theorem}{Validity and Unsatisfiability}{Validity and Unsatisfiability}
\textit{A formula F is valid if and only if \( \lnot F \) is unsatisfiable}.
\vspace{1em}
\noindent
\newline
\textit{Proof. Suppose  F is valid. Then for all interpretations \( \mathcal{I} \), we have \( \mathcal{I} \models F \), which implies \( \mathcal{I} \nvDash \lnot F \).}
\newline
Therefore, \( \lnot F \) is unsatisfiable.
\vspace{1em}
\noindent
\newline
Conversely, if \( \lnot F \) is unsatisfiable, then for all interpretations \( \mathcal{I} \), we have \( \mathcal{I} \nvDash \lnot F \), which implies 
\( \mathcal{I} \models F \). Therefore, \( F \) is valid.
\end{theorem}
\begin{theorem}{Satisfiability and Invalidity}{Satisfiability and Invalidity}
\textit{A formula F is satisfiable if and only if \( \lnot F \) is invalid}
\vspace{1em}
\noindent
\newline
\textit{Proof}. \( F \) is satisfiable if and only if there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models F \), which 
is equivalent to \( \mathcal{I} \nvDash \lnot F \). This is precisely the condition for \( \lnot F \) to be invalid.
\end{theorem}
These relationships demonstrate the duality between validity and unsatisfiability, and between 
satisfiability and invalidity, providing a complete characterization of the semantic landscape of first-order logic.
\section{Logical Consequence}
\subsection{The Three Fundamental Query Types}
Automated reasoning system must be capable of resolving three fundamental types of semantic queries:
\begin{itemize}
	\item \textbf{Satisfiability queries}: Is formula \( F \) satisfiable?
	\item \textbf{Validity queries}: Is formula \( F \) valid?
	\item \textbf{Logical consequence queries}: Does \( F \) follow logically from a set of hypotheses \( H \)?
\end{itemize}
\subsection{Definition of Logical Consequence}
\begin{definition}{Logical Consequence}{Logical Consequence}
Let \( H = \left\{ \phi_1, \phi_2, \ldots, \phi_n \right\} \) be a set of formulas (the \textbf{hypotheses} or \textbf{premises}) and let 
\( F \) be a formula (the \textbf{conclusion}). We say that \( F \) is a \textbf{logical consequence} of \( H \), written \( H \models F \), if:
\[
  H \models F \Leftrightarrow \text{ for all interpretations } \mathcal{I}, \text{ if } \mathcal{I} \models H \text{ then } \mathcal{I} \models F
\]
\end{definition}
In other words, \( F \) is a logical consequence of \( H \) if every model of \( H \) is also a model of \( F \). Here, \( \mathcal{I} \models H \)
means that \( \mathcal{I} \) satisfies all formulas in \( H \).
\subsection{The deduction Theorem}
The deduction theorem establishes a fundamental connection between logical consequence and validity, reducing the probem of checking entailment 
to the problem of checking validity.
\begin{definition}{Deduction theorem}{Deduction theorem}
\textit{Let H be a set of formulas and F be a formula}.
\newline
\textit{Then}:
\[
  H \models F \text{ iff } \models (H \rightarrow F)
\]
\textit{where \( H \rightarrow F \) denotes the implication from the conjunction of all formulas in H to F}
\end{definition}
\textit{Proof}. We prove both directions:
\newline
(\( \Rightarrow \)) Assume \( H \models F \). We must show that \( H \rightarrow F \) is valid, i.e., for all interpretations \( \mathcal{I} \), we have 
\( \mathcal{I} \models H \rightarrow F \).
\vspace{1em}
\noindent
\newline
Let \( \mathcal{I} \) be an arbitraty interpretation. By the semantics of implication, \( \mathcal{I} \models H \rightarrow F \), holds if 
either:
\begin{itemize}
	\item \( \mathcal{I} \nvDash H \) (the antecedent is false), or 
	\item \( \mathcal{I} \models F \) (the consequent is true)
\end{itemize}
If \( \mathcal{I} \nvDash H \), then \( \mathcal{I} \models H \rightarrow F \) trivially. If \( \mathcal{I} \models H \), then by the hypothesis
\( H \models F \), we have \( \mathcal{I} \models F \), so \( \mathcal{I} \models H \rightarrow F \). In both cases, \( \mathcal{I} \models H \rightarrow F \).
\vspace{1em}
\noindent
\newline
(\( \Leftarrow \)) Conversely, suppose \( H \rightarrow F \) is valid. Then for all interpretations \( \mathcal{I} \), we have \( \mathcal{I} \models H \rightarrow F \).
By the semantics of implications, for all \( \mathcal{I} \), either \( \mathcal{I} \nvDash H \) or \( \mathcal{I} \models F \). Therefore, for all 
\( \mathcal{I} \) such that \( \mathcal{I} \models H \), we must have \( \mathcal{I} \models F \), which the definition of \( H \models F \).
\subsection{Notational Ambiguity of \( \models \)}
The symbol \( \models \) is used in three distinct but related contexts:
\begin{itemize}
	\item \textbf{Satisfaction}: \( \mathcal{I} \models F \) means interpretation \( \mathcal{I} \) satisfies formula \( F \).
	\item \textbf{Validity}: \( \models F \) means formula \( F \) is valid (satisfied by all interpretations)
	\item \textbf{Entailment}: \( H \models F \) means formula \( F \) is a logical consequence of the set of formulas \( H \).
\end{itemize}
While this overloading may initially seem confusing, these three uses are smentically coherent and represent different aspects of the same fundamental 
semantic relation.
\subsection{Reduction to Unsatisfiability}
A fundamental result connects logical consequence to unsatisfiability, providing another characterization of entailment.
\begin{theorem}{Jey Theorem: Reduction to Unsatisfiability}{Jey Theorem: Reduction to Unsatisfiability}
\textit{Let H be a set of formulas and F be a formula. Then:}
\[
  H \models F \text{ iff } H \cup \left\{ \lnot F \right\} \text{ is unsatisfiable}
\]
\end{theorem}
\textit{Proof}. We prove both directions:
\vspace{1em}
\noindent
\newline
\( (\Rightarrow) \) Assume \( H \models F \). We must show that \( H \cup \left\{ \lnot F \right\} \) is unsatisfiable.
\vspace{1em}
\noindent
\newline
Suppose for contradiction that there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models H \cup \left\{ \lnot F \right\} \). Then 
\( \mathcal{I} \models H \), and \( \mathcal{I} \models \lnot F \), which implies \( \mathcal{I} \nvDash F \). However, sincer \( H \models F \) and \( \mathcal{I} \models H \),
we must have \( \mathcal{I} \models F \), which is a contradiction. Therefore, \( H \cup \left\{ \lnot F \right\} \) is unsatisfiable.
\vspace{1em}
\noindent
\newline
\( (\Leftarrow) \) Assume \( H \cup \left\{ \lnot F \right\} \) is unsatisfiable. We must show that \( H \models F \).
\vspace{1em}
\noindent
\newline
Let \( \mathcal{I} \) be any interpretation such that \( \mathcal{I} \models H \). Since \( H \cup \left\{ \lnot F \right\} \) is unsatisfiable,
there is no interpretation that satisfies both \( H \) and \( \lnot F \). Therefore, \( \mathcal{I} \nvDash \lnot F \), which implies \( \mathcal{I} \models F \). Since
this holds for all interpretations satisfying \( H \), we conclude that \( H \models F \).
\section{Refutational Reasoning}
\subsection{Proof by Contradiction}
\begin{definition}{Refutational reasoning (Proof by contradiction)}{Refutational reasoning (Proof by contradiction)}
\textbf{Refutational reasoning} (or \textbf{proof by refutation}) is a fundamental techinique in automated reasoning on the principle 
of \textit{reductio ad absurdum}. To prove that a conclusion \( F \) follows from hupotheses \( H \), we assume the negation of the conclusion 
and derive a contradiction.
\begin{enumerate}
	\item \textbf{Goal}: Prove \( H \models F \) (where \( H \) represents assumpions and \( F \) represents the conjecture) 
	\item \textbf{Method}: Show that \( H \cup \left\{ \lnot F \right\} \) is unsatisfiable 
	\item \textbf{Conclusion}: If \( H \cup \left\{ \lnot F \right\} \) is unsatisfiable, then \( H \models F \) by the previous theorem
\end{enumerate}
\end{definition}
\subsection{The refutational Framework}
The automated reasoning process can be formalized as follows:
\begin{center}
	\begin{tikzpicture}[>=stealth]
		% nodi principali
		\node (in) at (0,0) {$H \cup \{\neg F\}$};
		\node[draw] (dp) at (4,0) {Decision Procedure};
		\node (sat)   at (8,2.5)  {\textbf{Satisfiable}};
		\node (unsat) at (8,-2.5) {\textbf{Unsatisfiable}};
  
		% testi a destra
		\node[right=0.3cm of sat, text width=4.5cm, align=left]
	  	{Model found: counterexample to $H \models F$};
		\node[right=0.3cm of unsat, text width=4.5cm, align=left]
	  	{Proof found (refutation): $H \models F$};
  
		% frecce
		\draw[->] (in) -- (dp);
		\draw[->] (dp.north east) -- node[above left] {No}  (sat.south west);
		\draw[->] (dp.south east) -- node[below left] {Yes} (unsat.north west);
	\end{tikzpicture}
\end{center}
\textbf{Two possible outcomes}:
\begin{itemize}
	\item \textbf{Unsatisfiable}: The procedure derives a contradiction, producing a \textbf{refutation} (proof) that \( H \models F \).
	\item \textbf{Satisfiable}: The procedure finds a model \( \mathcal{I} \) of \( H \cup \left\{ \lnot F \right\} \), which serves as a \textbf{counterexample} showing that \( H \nvDash F \).
\end{itemize}
This refutational approach forms the foundation of modern automated theorem provers and SAT solvers, reducing the problem of proving logical consequence 
to the problem of detecting unsatisfiability.
\part{Free Variables and Satisfiability}
\section{Satisfiability of Formulas with Free Variables}
\subsection{The problem of Free Variables}
In our previous definition of statisfiability, we considered the semantics of logical connectives and 
quantifiers, but we did not fully address the tratment of \textbf{free variables}. Recall that a variable can 
be either:
\begin{itemize}
	\item \textbf{Bound}: The variable falls within the scope of a quantifier 
	\item \textbf{Free}: The variable does not fall within the scope of any quantifier
\end{itemize}
The presence of free variables requires careful consideration when determining satisfiability, as their 
interpretation depends on the variable assignment \( \beta \).
\subsection{Motivating Example}
Consider the following formula:
\[
  F: \forall x (f(x,x) = x \wedge R(x,y))
\]
The formula contains:
\begin{itemize}
	\item A bound variable \( x \) (qunatified by \( \forall \))
	\item A free variable \( y \) (not quantified)
\end{itemize}
\subsection{Semantic Evaluation with Free Variables}
To determine whether an interpretation \( \mathcal{I} = \langle D, \Phi \rangle \) with assignment \( \beta \) satisfies \( F \),
we write \( \mathcal{I} \models_{\beta} F \) and proceed as follows:
\vspace{1em}
\noindent
\newline
By semantics of universal quantification, we need to check that for all \( d \in D \):
\[
  \mathcal{I} \models_{\beta[x \leftarrow d]} (f(x,x) = x \wedge R(x,y))
\]
This requires verifiying both conjuncts under the updated assignment \( \beta[x \leftarrow d] \):
\vspace{1em}
\noindent
\newline
\textbf{First conjuction}: \( \mathcal{I} \models_{\beta[x \leftarrow d]} f(x,x) = x \)
\vspace{1em}
\noindent
\newline
This holds if and only if:
\[
  (\Phi(f)(d,d),d) \in \Phi(=)
\]
where \( \Phi(=) \) represents the identity relation. In other words, we require that \( \Phi(f)(d,d) = d \) for 
all \( d \in D \).
\vspace{1em}
\noindent
\newline
\textbf{Second conjunct}: \( \mathcal{I} \models_{\beta[x \leftarrow d] R(x,y)} \)
\vspace{1em}
\noindent
\newline
This holds if and only if:
\[
  (d, \beta(y)) \in \Phi(R)
\]
Let \( \beta(y) = d' \) for some \( d' \in D \). Then we require \( (d,d') \in \Phi(R) \) for all \( d \in D \).
\subsection{Existential Closure}
The key observation is that the satisfiability of a formula with free variables is intimately connected to its \textbf{existential closure}.
\begin{definition}{Existential Closure}{Existential Closure}
The existential closure of a formula \( F \), denoted \( \exists^* F \), is obtained by adding an existential quantifier for every free 
variable in \( F \).
\end{definition}
For example, if \( F \) contains free variables \( y_1,y_2, \ldots, y_n \) then:
\[
  \exists^* F = \exists y_1 \exists y_2 \ldots \exists y_n F
\]
Returning to our example, if we consider the existential closure by quantifying the free variable \( y \):
\[
  \exists y \forall x (f(x,x) = x \wedge R(x,y))
\]
Under this interpretation, we need to verify that there exists some \( d' \in D \) such that for all \( d \in D \).
\subsection{Satisfiability to Open Formulas}
We now provide the complete definition of satisfiability that handles both closed and open formulas.
\begin{definition}{Satisfiability - Complete Definition}{Satisfiability - Complete Definition}
A formula \( F \) is \textbf{satisfiable} if:
\begin{itemize}
	\item \textbf{Case 1 (Closed formula)}: If \( F \) is a sentece (contains no free variables), then \( F \) is satisfiable if there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models F \).
	\item \textbf{Case 2 (Open formula)}: If \( F \) contains free variables, then \( F \) is satisfiable if there exists and interpretation \( \mathcal{I} \) and a variable assignment \( \beta \) such that \( \mathcal{I} \models_{\beta} F \).
\end{itemize}
\end{definition}
\begin{theorem}{Satifiability and Existential Closure}{Satifiability and Existential Closure}
\textit{A formula F with free variables is satisfiable if and only if its existential closure \( \exists^* F \) is satisfiable}
\vspace{1em}
\noindent
\newline
\textit{Proof}. Let \(F \) be a formula with free variables \( y_1, \ldots, y_n \) and let \( \exists^* F = \exists y_1 \ldots \exists y_n F \).
\vspace{1em}
\noindent
\newline
\( (\Rightarrow) \) Suppose \( F \) is satisfiable. Then there exists and interpretation \( \mathcal{I} \) and assignment \( \beta \) such that 
\( \mathcal{I} \models_{\beta} F \). Let \( d_i = \beta(y_i) \) for \( i = 1, \ldots, n \). Then by the semantics of existential quantification applied repeadetly, \( \mathcal{I} \models \exists^* F \).
\vspace{1em}
\noindent
\newline
\( (\Leftarrow) \) Suppose \( \exists^* F \) is satisfiable. Then there exists an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models \exists y_1 \ldots \exists y_n F \).
By the semantics of existential quantification, there exist \( d_1, \ldots, d_2 \in D \) such that \( \mathcal{I} \models_{\beta[y_1 \leftarrow d_1, \ldots, y_n \leftarrow d_n]} \).
\end{theorem}
This result demonstrates that when checking satisfiability of formulas with free variables, we can equivalentlòy check the satisfiability of their existential closure, treating free 
variables as existentailly qunatified.
\subsection{Universal Closure and Validity}
Dually, we can consider the \textbf{universal closure} of a formula with free variables.
\begin{theorem}{Validity and Universal Closure}{Validity and Universal Closure}
\textit{A formula F with free variables is valid if and only if its universal closure \( \forall^* F \) is valid}.
\vspace{1em}
\noindent
\newline
The intuition is straightforwared: if \( F \) contains free variables, then \( F \) is valid if for all interpretations \( \mathcal{I} \) and 
for all assignments \( \beta \), we have \( \mathcal{I} \models_{\beta} F \). This is precisely the condition for the univesal 
closure \( \forall^* F \) to be valid.
\end{theorem}
\section{Decidability and Semidecidability in First-Order Logic}
\subsection{Computational Complexity of First-Order Logic}
While certain restricted fragments of first-order logic admit decision procedures, the general case 
present fundamental computational limitations:
\begin{definition}{Decidability in First-Order Logic}{Decidability in First-Order Logic}
\begin{itemize}
	\item \textbf{Unsatisfiability} in first-order logic is \textbf{semidecidable} (recursively enumerable)
	\item \textbf{Satisfiability} in first-order logic is \textbf{not even semidecidable}
\end{itemize}
\end{definition}
\textit{Note}. Recall that if a decision problem \( A \) is semidecidable and its complement \( \lnot A \) is also 
semidecidable, then \( A \) is decidable. The decision procedure can be obtained by running both 
semidecision procedures in parallel: if the instance belongs to \( A \), the first procedure will eventually terminate with "yes";
if the instance belogs to \( \lnot A \), the second procedure will eventually terminate with "yes".

\subsection{The need for Restricted Theories}
To obtain decision procedures, we must restrict out attention to \textbf{decidable fragments} of first-order logic. This motivates the study of 
\textbf{first-order theories} - logical systems with additional structure that enable algorithmic reasoning.
\section{First-Order Theories}
\subsection{Definition of a First-Order Theory}
\begin{definition}{First-Order Theory}{First-Order Theory}
A \textbf{first-order theory} is a pair \( \mathcal{T} = \langle \sigma, \mathcal{A} \rangle \) where:
\begin{itemize}
	\item \( \sigma \) is a \textbf{signature} (defining the vocabulary of the theory)
	\item \( \mathcal{A} \) is a set of \textbf{axioms} - closed formulas (sentences) that we assume to hold in all models of the theory
\end{itemize}
\end{definition}
The axioms define properties of specific symbols in the signature, giving them fixed interpretations across all models of the theory.
\subsection{The theory of Equality}
A fundamental example is the \textbf{theory of equality} \( \mathcal{T}_{E} = \langle \sigma_{E}, \mathcal{A}_{E} \rangle \).
\vspace{1em}
\noindent
\newline
\textbf{Signature}: The signature of the theory of equality is:
\[
  \sigma_{E} = \left\{ = \right\} \cup \mathcal{C} \cup \mathcal{F} \cup \mathcal{P}
\]
where:
\begin{itemize}
	\item \( = \) is the equality predicate (interpreted symbol)
	\item \( \mathcal{C} \) is a set of constant symbols (uninterpreted)
	\item \( \mathcal{F} \) is a set of function symbols (uninterpreted)
	\item \( \mathcal{P} \) is a set of predicate symbols (uninterpreted)
\end{itemize}
\textbf{Example signature}: Consider \( \sigma = \left\{ a,b,f,Q,= \right\} \). The symbols \( a,b,f,Q \) are \textbf{free} (uninterpreted), 
whereas = (equality) is \textbf{defined} by the axioms of the theory.
\subsection{Axioms of Equality}
The axiom set \( \mathcal{A}_{E} \) consists of formulas that characterize equality as a congruence relation.
\vspace{1em}
\noindent
\newline
\textbf{Equivalence relation axioms}:
\begin{align*}
	& \forall x\, (x = x) && \text{(Reflexivity)} \\
	& \forall x\, \forall y\, (x = y \rightarrow y = x) && \text{(Symmetry)} \\
	& \forall x\, \forall y\, \forall z\, ((x = y \wedge y = z) \rightarrow x = z) && \text{(Transitivity)}
\end{align*}
These three axioms establish that equality is an equivalance relation.
\vspace{1em}
\noindent
\newline
\textbf{Congruence axioms of function symbols}: For each function symbol \( f \in \mathcal{F} \) of arity \( n \):
\[
	\forall \overrightarrow{x}\, \forall \overrightarrow{y}\, (\bigwedge_{i = 1}^{n} x_i = y_i) \rightarrow f(x_1, \ldots, x_n) = f(y_1, \ldots, y_n) 
\]
where \( \overrightarrow{x} = (x_1, \ldots, x_n) \) and \( \overrightarrow{y} = (y_1, \ldots, y_n) \).
\vspace{1em}
\noindent
\newline
This axioms states that \( f \) respects equality: equal inputs produce equal outputs.\vspace{1em}
\noindent
\newline
\textbf{Congruence axioms for predicate sumbols}: For each predicate symbol \( R \in \mathcal{P} \) of arity \( n \):
\[
  \forall \overrightarrow{x}\, \forall \overrightarrow{y}\, (\bigwedge_{i = 1}^{n} x_i = y_i) \rightarrow (R(x_1, \ldots, x_n) \leftrightarrow R(y_1, \ldots, y_n))
\]
This axiom states that \( R \) resprects equality: the truth value of \( R \) depends only on the equivalence classes of its arguments.
\subsection{Models of a Theory}
\begin{definition}{\( \mathcal{T} \)-Model}{T-Model}
A \( \mathcal{T} \)\textbf{-Model} is an interpretation \( \mathcal{I} \) such that \( \mathcal{I} \models \mathcal{A} \) (i.e., \( \mathcal{I} \) satisfies 
all axiom in \( \mathcal{A} \)).
\end{definition}
\subsection{Satisfiability and Validity Relative to a Theory}
\begin{definition}{\( \mathcal{T} \)-Satisfiability}{T-Satisfiability}
A formula \( G \) is \( \mathcal{T} \)\textbf{-satisfiable} if there exists a \( \mathcal{T} \)-model \( \mathcal{I} \) such that 
\( \mathcal{I} \models G \).
\end{definition}
\begin{definition}{\( \mathcal{T} \)-Validity}{T-Validity}
A formula \( G \) is \( \mathcal{T} \)\textbf{-valid} if for all \( \mathcal{T} \)-models \( \mathcal{I} \), we have \( \mathcal{I} \models G \).
\vspace{1em}
\noindent
\newline
Equivalently, \( G \) is a logical consequence of the axioms: \( \mathcal{A} \models G \).
\end{definition}
\subsection{Example: Satisfiability vs. \( \mathcal{T}_{E} \)-Satisfiability}
Consider the set of formulas:
\[
  S = \left\{ P(a), \lnot P(b), a = b \right\}
\]
\textbf{Claim}: \( S \) is satisfiable in general first-order logic, but \( S \) is \textbf{not} \( \mathcal{T}_{E} \)\textbf{-satisfiable}.
\vspace{1em}
\noindent
\newline
\textit{Proof}. \textbf{Satisfiability}: We can construct an interpretation \( \mathcal{I} \) with domain \( D = \left\{ d_1, d_2 \right\} \) where:
\begin{itemize}
	\item \( \Phi(a) = d_1, \Phi(b) = d_2 \).
	\item \( \Phi(P) = \left\{d_1\right\} \).
	\item \( \Phi(=) = \left\{(d_1,d_1),(d_2,d_2),(d_1,d_2)(d_2,d_1) \right\} \) (universal relation)
\end{itemize}
Then \( \mathcal{I} \models P(a), \mathcal{I} \models \lnot P(b), \text{ and } \mathcal{I} \models a = b, \text{ so } \mathcal{I} \models S \).
\vspace{1em}
\noindent
\newline
\( \mathcal{T}_{E} \)\textbf{-Unsatisfiability}: In any \( \mathcal{T}_{E} \)-model, equality must satisfy the congruence axioms. 
If \( \mathcal{I} \models a = b, \text{ and } \mathcal{I} \models P(a) \), then by the congruence axiom for \( P \), we must have \( \mathcal{I} \models P(b) \), contradicting 
\( \mathcal{I} \models \lnot P(b) \). Therefore, no \( \mathcal{T}_{E} \)-model satisfies \( S \).
\vspace{1em}
\noindent
\newline
This example illustrate that satisfiability relative to a theory is more restrictive than general satisfiability, as models 
must respect the additional constraints imposed by the theory's axioms.
\section{Quantifiers-Free Fragments and Decidability}
\subsection{The Quantifier-Free Fragment of \( \mathcal{T}_{E} \)}
While the full theory of equality \( \mathcal{T}_{E} \) is undecidable, its \textbf{quantifier-free fragment} admits a decsion procedure.
\begin{definition}{Quantifier-Free Fragment}{Quantifier-Free Fragment}
The \textbf{quantifier-free fragment} of first-order logic consists of all formulas that do not contain quantifiers \( (\forall \text{ or } \exists) \).
\end{definition}
\vspace{1em}
\noindent
\newline
For a theory \( \mathcal{T} \), the quantifier-free fragment allows quantifiers to appear only in the axioms, not in the 
input formulas to be checked for satisfiability.
\vspace{1em}
\noindent
\newline
Our goal is to develop a decision procedure for the quantifier-free fragment of \( \mathcal{T}_{E} \). We will focus 
initially on deciding satisfiability for sets (or conjunctions) of literals, and then extend this to arbitrary quantifier-free formulas 
using normal forms.
\subsection{Normal Forms}
To handle arbitrary quantifier-free formulas, we introduce two important normal forms that facilitate systematic resoning.
\subsubsection{Negation Normal Form (NNF)}
\begin{definition}{Negation Normal Form}{Negation Normal Form}
A formula is in \textbf{Negation Normal Form (NNF)} if:
\begin{itemize}
	\item The only logical connectives are \( \wedge, \vee, \text{ and }, \lnot \).
	\item Negation \( (\lnot) \) applies only to atomic formulas (atoms)
\end{itemize}  
\end{definition}
Any quantifier-free formula can be converted to NNF by applying the following equivalence preserving transformations:
\begin{align*}
	& H \leftrightarrow G \equiv (H \rightarrow G) \wedge (G \rightarrow H) && \text{(Eliminate biconditional)} \\
	& H \rightarrow G \equiv \lnot H \vee G && \text{(Eliminate implication)} \\
	& \lnot(H \wedge G) \equiv \lnot H \vee \lnot G && \text{(De Morgan's law)} \\
	& \lnot(H \vee G) \equiv \lnot H \wedge \lnot G && \text{(De Morgan's law)} \\
	& \lnot \lnot H \equiv H && \text{(Double negation elimination)}
\end{align*}
\subsubsection{Disjunctive Normal Form (DNF)}
\begin{definition}{Disjunctive Normal Form}{Disjunctive Normal Form}
A formula is in \textbf{Disjunctive Normal Form (DNF)} if it is a disjunction of conjunctions of literals:
\[
  \bigvee_{i = 1}^{k} (\bigwedge_{j = 1}^{n_i} L_{i,j})
\]
where each \( L_{i,j} \) is a literal (an atomic formula or its negation)
\end{definition}
Equivalently, a DNF formula has the structure:
\[
  (L_{1,1} \wedge L_{1,2} \wedge \ldots L_{1,n_1}) \vee (L_{2,1} \wedge L_{2,2} \wedge \ldots \wedge L_{2,n_2}) \vee \ldots \vee (L_{k,1} \wedge L_{k,2} \wedge \ldots \wedge L_{k,n_k})
\]
\subsection{Conversion to DNF}
Any quantifier-free formula \( F \) can be systematically converted to an equivalent DNF formula throught a two-stage 
process:
\begin{center}
	\begin{tikzpicture}
		\node (F) {$F$};
		\node[draw, right=of F] (nnf) {Convert to NNF};
		\node[right=of nnf] (F1) {$F'$};
		\node[draw, right=of F1] (dnf) {Convert to DNF};
		\node[right=of dnf] (F2) {$F''$};
	
		\draw[->] (F) -- (nnf);
		\draw[->] (nnf) -- (F1);
		\draw[->] (F1) -- (dnf);
		\draw[->] (dnf) -- (F2);
	\end{tikzpicture}
\end{center}
\textbf{Stage 1}: Convert \( F \) to NNF using the transformations above, obtaining \( F'' \).
\vspace{1em}
\noindent
\newline
\textbf{Stage 2}: Convert \( F' \) to DNF by repeatedly applying the distributivity law:
\[
  H \wedge (G_1 \vee G_2) \equiv (H \wedge G_1) \vee (H \wedge G_2)
\]
This transformation pushes conjunctions inward and disjunctions outward,
resulting in a disjunction of conjunctions.
\subsection{Decision Procedure for Quantifier-Free \( \mathcal{T}_{E} \)} 
The decision procedure operates on conjunctions of literals. Given a set (or conjunctions) \( S \) of literals:
\begin{center}
	\begin{tikzpicture}[>=stealth]
	  % Nodo centrale (rettangolo)
	  \node[draw, rectangle] (dp) {Decision Procedure for $\mathrm{QF}\mathcal{T}_E$};
	
	  % Input a sinistra
	  \node[left=of dp] (in) {$S$ (conjunction of literals)};
	
	  % Output
	  \node[above right=1.5cm and 1.5cm of dp] (sat) {\textbf{Satisfiable}};
	  \node[below right=1.5cm and 1.5cm of dp] (unsat) {\textbf{Unsatisfiable}};
	
	  % Frecce
	  \draw[->] (in) -- (dp);
	  \draw[->] (dp.north) -- (sat);
	  \draw[->] (dp.south) -- (unsat);
	\end{tikzpicture}
\end{center}
\textbf{Extension to arbitrary quantifier-free formulas}: For a general quantifier-free formula \( F \):
\begin{enumerate}
	\item Convert \( F \) to NNF, obtaining \( F' \).
	\item Convert \( F' \) to DNF, otaining \( F'' = \wedge_{i = 1}^{k} \mathcal{C}_i \) where each \( \mathcal{C}_i \) is a conjunction of literals 
	\item Apply the decision procedure to each conjunction \( \mathcal{C}_i \).
	\item \( F \) is satisfiable if and onlu if at least one \( \mathcal{C}_i \) is satisfiable
\end{enumerate}
This reduction allows us to decide satisfiability for arbitrary quantifier-free formulas by deciding satisfiability 
for each disjunct independently.
\subsection{Elimination of Non-Equality Predicates}
The decision procedure for quantifier-free \( \mathcal{T}_{E} \) assumes that the only predicate symbol in the formula is equality (=). However,
formulas may contain additional predicate symbols. We now show how to elinate such predicates throught a satisfiability-preserving transformation.
\subsubsection{The Transformation}
\begin{definition}{Predicate Elimination}{Predicate Elimination}
Given an occurence of a predicate symbol \( P \) of arity \( n \) applied to terms \( t_1, \ldots, t_n \), we eliminate \( P \) by introducing:
\begin{itemize}
	\item A fresh function symbol \( f_P \) (one for each predicate symbol \( P \neq = \))
	\item A fresh constant symbol \( \bullet \) (the same constant for all predicates)
\end{itemize}
The transformation replaces predicate applications with equality constraints:
\[
  P(t_1, \ldots, t_n) \mapsto f_P(t_1, \ldots, t_n) = \bullet 
\]
\[
  \lnot P(t_1, \ldots, t_n) \mapsto f_P(t_1, \ldots, t_n) \neq \bullet
\]
\end{definition}
\textbf{Intuition}: The predicate \( P(t_1, \ldots, t_n) \) is true if and only if the term \( f_p(t_1, \ldots, t_n) \) evaluates to 
the distinguished constant \( \bullet \).
\subsubsection{Satisfiability Preservation}
\begin{theorem}{Satisfiability Preservation}{Satisfiability Preservation} 
\textit{Let F be a quantifier-free formula and let F' be the result of applying predicate elimination to F. 
Then F is satisfiable if and only if F' is satisfiable in models with cardinality greater than 1}.
\vspace{1em}
\noindent
\newline
\textit{Note}. The restriction to models with cardinality greater than 1 is necessary to avoid trivial models.
In a model with domain \( D = \left\{d\right\} \) (cardinality 1), all terms evaluate to the same element \( d \), 
making all equalities trivially true and potentially invalidating the transformation.
\end{theorem}
\subsubsection{Example: The Need for Cardinality Restriction}
Consider the following two formulas:
\vspace{1em}
\noindent
\newline
\textbf{Original formula}:
\[
  S_1 = \left\{\forall x\, \forall y\, (x = y), \lnot P(a) \right\}
\]
This formula is \( \mathcal{T}_{E} \)-satisfiable. We can construct a model with domain \( D = \left\{d_1,d_2\right\} \) where:
\begin{itemize}
	\item \( \Phi(a) = d_1 \).
	\item \( \Phi(P) = \left\{ d_2 \right\} \) (so \( d_1 \notin \Phi(P) \), making \( \lnot P(a) \) true)
	\item The first axiom \( \forall x\, \forall y\, (x = y) \) is vacuously false in this model, but if we interpret it as 
		requiring equality to be universal, we need a different construction
\end{itemize}
Actually, let's reconsider: \( \left\{ \forall x\, \forall y\, (x = y), \lnot P(a) \right\} \) asserts that all elements are equal 
(domain has cardinality 1) and \( P(a) \) is false. This is satisfiable in a model with \( D = \left\{d\right\}, \Phi(a) = d \),
and \( \Phi(P) = \varnothing \).
\vspace{1em}
\noindent
\newline
\textbf{Transformed formula}:
\[
  S_2 = \left\{ \forall x\, \forall y\, (x = y), f_P(a) \neq \bullet \right\}
\]
In a model with cardinality 1, we have \( D = \left\{d\right\} \), so \( \Phi(f_P)(d) = d \) and \( \Phi(\bullet) = d \). Therefore,
\( f_P(a) = \bullet \), contradicting \( f_P(a) \neq \bullet \). Thus \( S_2 \) is unsatisfiable in models of cardinality 1.
\vspace{1em}
\noindent
\newline
This example demonstrates that the transformation preserves satisfiability only when we exclude trivial models with cardinality 1.
\subsection{Treatment of Free Variables}
In quantifier-free formulas, free variables may appear. For the purpose of satisfiability checking,
free variables are treated analogously to constants.
\vspace{1em}
\noindent
\newline
\textit{Note}. (Free Variables as Constants). To determine satisfiability of a formula \( F \) with free variables
\( x_1, \ldots, x_k \), we need to find an interpretation \( \mathcal{I} \) and an assignment \( \beta \) such that \( \mathcal{I} \models_{\beta} F \).
\vspace{1em}
\noindent
\newline
Equivalently, we can treat each free variable \( x_i \) as a fresh constant symbol \( c_i \) and check satisfiability of the resulting 
closed formula. The formula is satisfiable if and only if there exists domain elements that can be assigned to these constants to satisfy the formula.
\vspace{1em}
\noindent
\newline
This observation allows us to reduce the satisfiability problem for formulas with free variables 
to the satisfiability problem for closed formulas by a simple syntactic substitution.
\section{The Congruence Closure Algrithm}
\subsection{Motivating Example}
Consider the following conjunction of literals:
\[
  x = g(x) \wedge f(x,g(g(x))) \neq g(x) \wedge f(x,x) = g(g(x))
\]
\textbf{Question}: Is this formula satisfiable or unsatisfiable?
\vspace{1em}
\noindent
\newline
\textbf{Intuitive analysis}: This formula appears to be unsatisfiable. From \( x = g(x) \), we can derive \( g(x) = g(g(x)) \) by applying 
the function \( g \) to both sides (congruence). Then from \( f(x,x) = g(g(x)) \) and the derived equality \( g(x) = g(g(x)) \), we obtain \( f(x,x) = g(x) \). 
But we also have \( x = g(x) \), so by congruence on \( f \), we get \( f(x,x) = f(x,g(x)) \). However, we need to check whether 
\( f(x,g(g(x))) = g(x) \) follows from the positive equalities, which would contradict \( f(x,g(g(x))) \neq g(x) \).
\subsection{The congruence closure Decision Procedure}
\begin{definition}{Congruence Closure Algorithm}{Congruence Closure Algorithm}
The \textbf{congruence closure algorithm} is a decision procedure for satisfiability in the quantifier-free fragment 
of the theory of equality. The algorithm operates as follows:
\begin{enumerate}
	\item \textbf{Build the smallest congruence}: Construct the smallest congruence relation that satisfies all postive equalities in the input formula 
	\item \textbf{Check negative equalities}: For each negative equality \( s \neq t \) in the input, check whether \( s \) and \( t \) belong to the same equivalence class in the congruence
	\item \textbf{Determine satisfiability}:
	\begin{itemize}
		\item If any pair \( (s,t) \) with \( s \neq t \) belongs to the same equivalence class, the formula is \textbf{unsatisfiable}
		\item Otherwise, the congruence provides a model, and the formula is \textbf{satisfiable}
	\end{itemize}
\end{enumerate}
\end{definition}
The key insight is that the smallest congruence containing all positive equalities is included in every congruence 
that satisfies those equalities. Therefore, if a negative equality is violeted in the smallest congruence, it must be violated in 
every model.
\subsection{Equivalence Relations and Partitions}
Before describing the algorithm in detail, we recall fundamental properties of equivalence relations.
\begin{definition}{Equivalence Relation}{Equivalence Relation}
An \textbf{equivalence relation} \( R \) on a set \( S \) is a binary relation that is:
\begin{itemize}
	\item \textbf{Reflexive}: \( \forall s \in S, sRs \).
	\item \textbf{Symmetric}: \( \forall s,t \in S, sRt \Rightarrow tRs \).
	\item \textbf{Transitive}: \( \forall s,t,u \in S, (sRt \wedge tRu) \Rightarrow sRu \).
\end{itemize}
\end{definition}
\begin{definition}{Equivalence Class}{Equivalence Class}
Given an equivalence relation \( R \) on set \( S \), the \textbf{equivalence class} of an element \( s \in S \) is:
\[
  [s]_R = \left\{s' \in S \;|\; s'Rs \right\}
\]
\end{definition}
\begin{definition}{Quotient Set}{Quotient Set}
The \textbf{quotient set} \( S/R \) is the set of all equivalence classes:
\[
  S/R = \left\{ [s]_R \;|\; s \in S \right\}
\]
\end{definition}
\begin{definition}{Partition Property}{Partition Property}
\textit{An equivalence relation R on S induces a parittion of S. That is, for any two distinct equivalence classes 
\( [s]_R \) and  \( [p]_R \)}:
\[
  s\nsim_R p \quad \Rightarrow \quad [s]_R \cap [p]_R = \varnothing
\]
\textit{where \( s \backsim_R p \) denotes sRp}
\vspace{1em}
\noindent
\newline
\textit{Conversely, every element belongs to exactly one equivalence class, and the union of all equivalence classes equals S}.
\end{definition}
This partition property is fundamental to the congruence closure algorithm, as it allows us to represent the congruence relation efficiently using 
a union-find data structure.
\part{Decision Procedures for Quantifier-Free Theories}
\section{The Congruence Closure Algorithm}
\subsection{Computing Congruence Closure}
We now describe how to compute the congruence closure for the quantifier-free fragment of the theory 
of equality \( \mathcal{T}_{E} \).
\subsubsection{Input Problem Structure}
Consider an input formula \( F \) consisting of a conjunction of equality and disequality literals:
\[
  F = \underbrace{\left\{ s_1 = t_1, \ldots, s_n = t_n \right\}}_{F^+} \cup \underbrace{\left\{s_{n + 1} \neq t_{n + 1}, \ldots, s_{n + m} \neq t_{n + m} \right\}}_{F^-}
\]
where:
\begin{itemize}
	\item \( F^+ \) denotes the set of \textbf{positive equalities} (equations)
	\item \( F^- \) denotes the set of \textbf{negative equalities} (disequations)
\end{itemize}
The congruence closure algorithm will construct the smallest congruence containing all equalities in \( F^+ \),
then check whether any disequality \( F^- \) is violated.
\subsubsection{Equivalence relations and Representatives}
Given a binary equivalence relation \( R \subseteq S \times S \) on a set \( S \), we can construct its quotient:
\[
  S/R = \left\{ [s]_R \;|\; s \in S \right\}
\]
where the equivalence class of \( s \) is:
\[
  [s]_R = \left\{ p \in S \;|\; pRs \right\}
\]
The element \( s \) is called a \textbf{representative} of the equivalence class \( [s]_R \).
\subsubsection{Disjointness of Equivalence Classes}
\begin{definition}{Disjoint Class}{Disjoint Class}
\textit{For any two equivalence classes \( [s_1]_R \) and \( [s_2]_R \), either they are identical or the 
are disjoint}:
\[
  [s_1]_R \cap [s_2]_R \neq \varnothing \quad \Rightarrow \quad [s_1]_R = [s_2]_R
\]
\textit{Proof}. Suppose there exists \( p \in [s_1]_R \cap [s_2]_R \). Then:
\begin{itemize}
	\item \( p R s_1 \) (since \( p \in [s_1]_R \))
	\item \( p R s_2 \) (since \( p \in [s_2]_R \))
\end{itemize}
\end{definition}
By symmetry and transitivity of \( R \), we have \( s_1 R s_2 \). Therefore, for any \( q \in [s_1]_R \), we have \( q R s_1 \) and
\( s_1 R s_2 \), so by transitivity \( q R s_2 \), which means \( q \in [s_2]_R \). Similarly, \( [s_2]_R \subseteq [s_1]_R \). Thus 
\( [s_1]_R = [s_2]_R \).
\subsubsection{Example: Equivalence Closure}
Consider the binary relation:
\[
  R = \left\{ (a,b),(b,c),(d,d) \right\}
\]
We can visualize this as a directed graph:
\begin{figure}
	\begin{tikzpicture}[->, node distance = 1.8cm]
		\node (a) {$a$};
		\node (b) [right=of a] {$b$};
		\node (c) [right=of b] {$c$};
		\node (d) [right=2.5cm of c] {$d$};

		\draw (a) -- (b);
		\draw (b) -- (c);
		\draw (d) edge [loop right] ();
	\end{tikzpicture}
\end{figure}
The \textbf{equivalence closure} \( R^* \) of \( R \) must include:
\begin{itemize}
	\item \textbf{Reflexivity}: \( (a,a),(b,b),(c,c),(d,d) \).
	\item \textbf{Symmetry}: \( (b,a),(c,b) \).
	\item \textbf{Transitivity}: \( (a,c),(c,a) \).
\end{itemize}
Thus:
\[
  R^* = \left\{ (a,a),(a,b),(a,c),(b,a),(b,b),(b,c),(c,a),(c,b),(c,c)(d,d) \right\}
\]
The quotient set is:
\[
  S/R^* = \left\{ \left\{a,b,c \right\}, \left\{d\right\} \right\}
\]
\begin{definition}{Equivalence Closure}{Equivalence Closure}
Given a binary relation \( R \) on set \( S \), the \textbf{equivalence closure} of \( R \), denoted \( R^* \), is the 
\( \subseteq \)-smallest equivalence relation such that:
\begin{enumerate}
	\item \( R^* \) is an equivalence relation 
	\item \( R \subseteq R^* \)
\end{enumerate}
Equivalently, \( R^* \) is the intersection of all equivalence relations containing \( R \).
\end{definition}
The equivalence closure can be computed by iteratively applying reflexivity, symmetry, and transitivity rules 
until a fixed point is reached.
\subsubsection{Understanding the \( \subseteq \)-Smallest Property}
\begin{definition}{Minimality of Equivalence Closure}{Minimality of Equivalence Closure}
\textit{Let R be a binary relation and \( R^* \) be its equivalence closure. For any equivalence relation P such that
\( R \subseteq P \), we have \( R^* \subseteq P \).}
\end{definition}
This means that \( R^* \) is the \textbf{smallest} equivalence relation containing \( R \) with respect to the subset ordering \( \subseteq \).
\begin{definition}{Congruence Closure}{Congruence Closure}
Given a binary relation \( R \), the \textbf{congruence closure} of \( R \), denoted \( R_{cong}^{*} \) is the 
\( \subseteq \)-smallest relation such that:
\begin{enumerate}
	\item \( R_{cong}^{*} \) is a congruence relation 
	\item \( R \subseteq R_{cong}^{*} \)
\end{enumerate}
\end{definition}
A congruence relation is an equivalence realtion that is preserved under function application: if 
\( s_1 \backsim t_1, \ldots, s_n \backsim t_n \), then \( f(s_1, \ldots, s_n) \backsim f(t_1, \ldots, t_n) \) for all function 
symbols \( f \).
\subsubsection{Example: Refinement of Equivalence Relations}
To illustrate the concept of one equivalence relation being smaller (finer) than another, consider 
the following example on the natural numbers \( \mathbb{N} \).
\vspace{1em}
\noindent 
\newline
\textbf{Equivalence modulo 2}: Define the relation \( \equiv_2 \subseteq \mathbb{N} \times \mathbb{N} \) by:
\[
  n \equiv_2 m \quad \text{iff} \quad n \equiv m \text{ (mod 2)}
\] 
\begin{center}
	\begin{tikzpicture}
		\draw (0,0) circle (2cm);
		\node at (0,2.25) {$\mathbb{N}/{\equiv_2}$};

		\draw[dashed, gray] (0,-2) -- (0,0.4);

		\node[orange!80!black] at (-0.6,0.9) {$[0]_2$};
		\node[orange!80!black] at (0.6,0.9) {$[1]_2$};
		\node at (-0.75,0.4) {(even)};
		\node at (0.75,0.4) {(odd)};
	\end{tikzpicture}
\end{center}
\textbf{Equivalence modulo 4}: Define the relation \( \equiv_4 \subseteq \mathbb{N} \times \mathbb{N} \) by:
\[
  n \equiv_4 m \quad \text{iff} \quad n \equiv m \text{ (mod 4)}
\]
This relation partitions \( \mathbb{N} \) into four equivalence classes:
\begin{center}
	\begin{tikzpicture}
		\draw (0,0) circle (2cm);
		\node at (0,2.25) {$\mathbb{N}/{\equiv_4}$};

		\draw[dashed, gray] (0,-2) -- (0,-0.4);
		\draw[dashed, gray] (0,-0.4) -- (2,-0.4);

		\node[orange!80!black] at (-0.7,0.9) {$[0]_4$};
		\node[orange!80!black] at (0.7,0.9) {$[1]_4$};
		\node[orange!80!black] at (-0.7,-1.0) {$[2]_4$};
		\node[orange!80!black] at (0.7,-1.0) {$[3]_4$};
	\end{tikzpicture}
\end{center}
\begin{definition}{Refinement}{Refinement} 
\textit{The relation \( \equiv_4 \) is a \textbf{refinement} of \( \equiv_2 \). That is:}
\[
  n \equiv_4 m \quad \Rightarrow \quad n \equiv_2 m
\]
\textit{However, the converse does not hold}:
\[
  n \equiv_2 m \quad \nRightarrow \quad n \equiv_4 m
\]
\textit{Proof}. If \( n \equiv_4 m \), then \( n \equiv m \) (mod 4), which means \( n - m = 4k \) for some \( k \in \mathbb{Z} \).
Therefore, \( n - m = 2(2k) \), so \( n \equiv m \) (mod 2), i.e., \( n \equiv_2 m \).
\vspace{1em}
\noindent
\newline
For the converse, consider \( n = 0 \) and \( m = 2 \). Then \( n \equiv_2 m \) (both are even), but \( n \mathrel{\not\equiv_4} m \) (since 
\( 0 \equiv 0 \) (mod 4) and \( 2 \equiv 2 \) (mod 4)).
\end{definition}
\textbf{Set-theoretic interpretation}: This means that \( (n,m) \in \equiv_4 \Rightarrow (n,m) \in \equiv_2 \), so:
\[
  \equiv_4 \subseteq \equiv_2
\]
In this sense, \( \equiv_4 \) is \textbf{strictly smaller} than \( \equiv_2 \) (it is a proper subset), and provides a finer 
partition of \( \mathbb{N} \).
\subsection{The Congruence Closure Decision Procedure}
We now return to the main problem: deciding satisfiability for quantifier-free formula in the theory of equality.
\subsubsection{Algorithm Description}
Recall that the input formula \( F \) has the form:
\[
  F = \underbrace{\left\{s_1 = t_1, \ldots, s_n = t_n \right\}}_{F^+} \cup \underbrace{\left\{s_{n + 1} \neq t_{n + 1}, \ldots, s_{n + m} \neq t_{n + m}\right\}}_{F^-}
\]
The congruence closure algorithm proceeds as follows:
\begin{algorithm}
\caption{Congruence Closure Decision Procedure}
\begin{algorithmic}[1]
	\Require Formula $F = F^+ \cup F^-$
	\State Compute the congruence closure $\mathrm{CC}(F^+)$ of the positive equalities
	\For{$i = n + 1$ \textbf{to} $n + m$}
		\If{$(s_i, t_i) \in \mathrm{CC}(F^+)$}
			\State \Return UNSATISFIABLE 
		\EndIf
	\EndFor
	\State \Return SATISFIABLE
\end{algorithmic}
\end{algorithm}
\textbf{Step 1}: Compute \( \mathrm{CC}(F^+) \), the smallest congruence relation containing all pairs \( (s_i,t_i) \) for \( i = 1, \ldots, n \).
\vspace{1em}
\noindent
\newline
\textbf{Step 2}: For each disequality \( s_i \neq t_i \) in \( F^- \) (where \( n + 1 \leq i \leq n + m \)), check 
whether \( (s_i, t_i) \) belongs to the same equivalence class in \( \mathrm{CC}(F^+) \).
\vspace{1em}
\noindent
\newline
\textbf{Step 3}: 
\begin{itemize}
	\item If \( (s_j, t_j) \in \mathrm{CC}(F^+) \) for some \( j \) with \( n + 1 \leq j \leq n + m \), then \( F \) is \textbf{unsatisfiable}
	\item Otherwise, \( F \) is \textbf{satisfiable}
\end{itemize}
\begin{center}
	\begin{tikzpicture}[->, node distance = 2cm]
		\node (input) {$F = F^+ \cup F^-$};
		\node[draw, right=of input] (box) {Compute $\mathrm{CC}(F^+)$};
		\node[above right=1.8cm and 2.2cm of box] (sat) {\textbf{SATISFIABLE}};
		\node[below right=1.8cm and 2.2cm of box] (unsat) {\textbf{UNSATISFIABLE}};

		\draw (input) -- (box);
		\draw (box.north east) -- (sat);
		\draw (box.south east) -- (unsat);
	\end{tikzpicture}
\end{center}
\subsubsection{Correctness of the Algorithm}
\begin{theorem}{Soundness and Completeness}{Soundness and Completeness}
\textit{The congruence closure algorithm is sound and complete for deciding satisfiability in the quantifier-free fragment 
of \( \mathcal{T}_{E} \)}.
\vspace{1em}
\noindent
\newline
\textit{Proof sketch}. \textbf{Soundness (Unsatisfiability)}: Suppose there exists \( j \) with \( n + 1 \leq j \leq n + m \) such that \( (s_j, t_j) \in \mathrm{CC}(F^+) \)
\end{theorem}
Since \( \mathrm{CC}(F^+) \) is the smallest congruence relation containing \( F^+ \), the pair \( (s_j, t_j) \) must belong 
to \textit{every} congruence relation that contains \( F^+ \).
\vspace{1em}
\noindent
\newline
Therefore, in any model \( \mathcal{I} \) that satisfies all equalities in \( F^+ \), we must have \( \mathcal{I} \models s_j = t_j \). But
\( F \) also contains \( s_j \neq t_j \), so \( \mathcal{I} \nvDash s_j \neq t_j \). Thus, no model can satisfy both \( F^+ \) and \( F^- \), making 
\( F \) unsatisfiable.
\vspace{1em}
\noindent
\newline
\textbf{Completeness (Satisfiability)}: If \( (s_i, t_i) \notin \mathrm{CC}(F^+) \) for all \( i \) with \( n + 1 \leq i \leq n + m \), then 
we can contruct a model by interpreting the equivalence classes of \( \mathrm{CC}(F^+) \) as domain elements.
This model satisfies all equalities in \( F^+ \) (by construction) and all disequalities in \( F^- \) (since the terms belong to 
different equivalence classes).
\vspace{1em}
\noindent
\newline
The key insight is that the congruence closure captures exactly those equalities that are \textit{forced} by the positive 
equalities in \( F^+ \) together with the congruence axioms of equality.
\subsection{Examples: Manual Execution}
We now illustrate the congruence closure algorithm with concrete Examples
\subsubsection{Notation and Setup}
For a formula \( F \) on the form:
\[
  F = \left\{s_1 = t_1, \ldots, s_n = t_n \right\} \cup \left\{s_{n + 1} \neq t_{n + 1}, \ldots, s_{n + m} \neq t_{n + m} \right\}
\]
we define \( S_F \) as the \textbf{set of all terms} that appear in \( F \).
\subsubsection{Example 1}
Consider the formula:
\[
  F = \left\{ x = g(x), f(x,x) = g(g(x)), f(x,g(g(x))) \neq g(x) \right\}
\]
The set of terms is:
\[
  S_F = \left\{x,g(x), f(x,x), g(g(x)), f(x,g(g(x))) \right\}
\]
\textbf{Notation}:
\begin{itemize}
	\item \( x \) is a \textbf{free variable symbol}
	\item \( f \) is a \textbf{binary function symbol} (arity 2)
	\item \( g \) is a \textbf{unary function symbol} (arity 1)
\end{itemize}
\textbf{Positive equalities}: \( F^+ = \left\{ x = g(x), f(x,x) = g(g(x)) \right\} \).
\vspace{1em}
\noindent
\newline
\textbf{Negative equalities}: \( F^- = \left\{f(x,g(g(x))) \neq g(x) \right\} \).
\subsubsection{Example 2}
Consider the formula:
\[
	F = \left\{ f(a,b) = a, f(f(a,b),b) \neq a \right\}
\]
The set of terms is:
\[
  S_F = \left\{ f(a,b),a,b,f(f(a,b),b) \right\}
\]
\textbf{Notation}:
\begin{itemize}
	\item \( a,b \) are \textbf{constant symbols} (by convention)
	\item \( f \) is a \textbf{binary function symbol}
\end{itemize}
\textbf{Positive equalities}: \( F^+ = \left\{f(a,b) = a \right\} \).
\vspace{1em}
\noindent
\newline
\textbf{Negative equalities}: \( F^- = \left\{f(f(a,b),b) \neq a \right\} \).
\vspace{1em}
\noindent
\newline
\textit{Note} (Free Varialbes vs. Constants). In the quantifier-free fragment, all variables are free. From a semantic 
perspective, free variables and constants can be used interchangeably: both are interpreted as arbitraty elements of the 
domain. The distinction is purely syntactic.
\subsubsection{Step-by-Step Execution for Example 1}
We now execute the congruence closure algorithm on Example 1:
\[
	F = \left\{ x = g(x), f(x,x) = g(g(x)), f(x,g(g(x))) \neq g(x) \right\}
\]
\textbf{Step 1: Initialize the partition}
\vspace{1em}
\noindent
\newline
Create a partition of \( S_F \) where every term is in its own singleton equivalence class:
\[
  \left\{ \left\{ x \right\}, \left\{g(x) \right\}, \left\{f(x,x) \right\}, \left\{f(x,g(g(x))) \right\} \right\}
\]
\textbf{Step 2: Process positive equalities}
\vspace{1em}
\noindent
\newline
For each equality \( (s_i = t_i) \in F^+ \) (for all \( i \) with \( 1 \leq i \leq n \)):
\begin{itemize}
	\item Unite the equivalence class of \( s_i \) with the equivalence class of \( t_i \).
	\item Unite the classes of all terms in \( S_F \) that become congruent as a consequence of \( s_i = t_i \).
\end{itemize}
\textbf{Processing} \( x = g(x) \):
\vspace{1em}
\noindent
\newline
Merge the classes \( \left\{x\right\} \) and \( \left\{g(x)\right\} \):
\[
  \left\{ \left\{ x,g(x) \right\}, \left\{f(x,x) \right\}, \left\{g(g(x)) \right\}, \left\{f(x,g(g(x))) \right\} \right\}
\]
Since \( x = g(x) \), by congruence we derive \( g(x) = g(g(x)) \) (applying \( g \) to both sides). Merge these classes:
\[
	\left\{ \left\{x,g(x),g(g(x)) \right\}, \left\{f(x,x) \right\}, \left\{f(x,g(g(x))) \right\} \right\}
\]
\textbf{Processing} \( f(x,x) = g(g(x)) \):
\vspace{1em}
\noindent
\newline
Since \( g(g(x)) \in \left\{x,g(x),g(g(x)) \right\} \) and \( f(x,x) \in \left\{f(x,x) \right\} \), merge these classes:
\[
  \left\{ \left\{ x,g(x),g(g(x)),f(x,x) \right\}, \left\{ f(x,g(g(x))) \right\} \right\}
\]
Now check for congruence: since \( x \sim g(g(x)) \) (both in the same class), we have:
\[
  f(x,x) \sim f(x,g(g(x)))
\]
by the congruence property (both arguments are in the same equivalence classes). Merge these classes:
\[
	\left\{ \left\{ x,g(x),g(g(x)),f(x,x),f(x,g(g(x))) \right\} \right\}
\]
\textbf{Step 3: Check negative equalities}
\vspace{1em}
\noindent
\newline
Check whether \( (s_i, t_i) \in \mathrm{CC}(F^+) \) for all \( i \) with \( n + 1 \leq i \leq n + m \).
\vspace{1em}
\noindent
\newline
For the disequality \( f(x,g(g(x))) \neq g(x) \):
\begin{itemize}
	\item \( f(x,g(g(x))) \in \left\{ x,g(x),g(g(x)),f(x,x),f(x,g(g(x))) \right\} \).
	\item \( g(x) \in \left\{x,g(x),g(g(x)),f(x,x),f(x,g(g(x))) \right\} \)
\end{itemize}
Both terms are in the same equivalence class, so \( (f(x,g(g(x))), g(x)) \in \mathrm{CC}(F^+) \).
\vspace{1em}
\noindent
\newline
\textbf{Conclusion}: The formula \( F \) is \textbf{UNSATISFIABLE}.
\section{Implementation of Congruence Closure on a DAG}
\subsection{DAG Representation}
The congruence closure algorithm can be implemented efficiently using a \textbf{Directed Acyclic Graph (DAG)} 
representation of the terms.
\vspace{1em}
\noindent
\newline
Consider the formula:
\[
  F = \left\{ x = g(x), f(x,x) = g(g(x)) \right\} \cup \left\{ f(x,g(g(x))) \neq g(x) \right\} 
\]
The set of terms is:
\[
  S_F = \left\{ x, g(x), g(g(x)), f(x,x), f(x,g(g(x))) \right\}
\]
We represent these terms as a graph where:
\begin{itemize}
	\item Each term is a node 
	\item Edges connect function symbols to their arguments 
	\item We use \( g \) and \( g' \) to distinguish the two applications of function \( g \)  
	\item We use \( f \) and \( f' \) to distinguish the two applications of function \( f \)
\end{itemize}
\begin{center}
	\begin{tikzpicture}[
		>=Stealth,
		fn/.style  = {draw, rectangle, minimum size=0.8cm, thick},
		var/.style = {draw, circle,    minimum size=0.8cm, thick},
		lbl/.style = {font=\small} 
	]
		% nodi 
		\node[fn]  (gp) at (0,3)     {$g'$};
		\node[fn]  (fp) at (2.5,3)   {$f'$};
		\node[fn]  (g)  at (0,1.5)   {$g$};
		\node[fn]  (f)  at (5.5,1.5) {$f$};
		\node[var] (x)  at (2.5,0)   {$x$};

		% archi 
		\draw[->] (gp) -- (g);
		\draw[->] (fp) to[bend left=10] node[above, lbl] {$g(g(x))$} (gp);
		\draw[->] (fp) to[bend right=15] (x);
		\draw[->] (g) -- (x);
		\draw[->] (f) to[bend right=20] (x);
		\draw[->] (f) to[bend left=20]  (x);

		% etichette dei termini
		\node[lbl, anchor=south west] at (fp.north east) {$f(x,g(g(x)))$};
		\node[lbl, right=0.3cm of g] {$g(x)$};
		\node[lbl, right=0.3cm of f] {$f(x,x)$};
		\node[lbl, below=0.1cm of x] {$x$};
		
	\end{tikzpicture}
\end{center}
The graph shoes the structure of the terms:
\begin{itemize}
	\item Node \( g \) has and edge to \( x \) (representing \( g(x) \))
	\item Node \( f \) has two edges to \( x \) (representing \( f(x,x) \))
	\item Node \( g' \) has and edge to \( g \) (representing \( g(g(x)) \)) 
	\item Node \( f' \) has edges to \( x \) and \( g' \) (representing \( f(x,g(g(x))) \))
\end{itemize}
This is a graph representation of the term structure, which allows efficient implementation of the congruence 
closure algorithm using union-find data structures to track equivalence classes of nodes.
\begin{definition}{Node Data Structure}{Node Data Structure}
Each mode in the DAG is represented by a data structure with the following fields:
\begin{lstlisting}[style=ocamlpseudo]
	type node = {
		id: Id;
		fn: String;
		args: Id list;
		mutable find: Id;
		mutable ccpar: Id set;
	}
\end{lstlisting}
For a node \( n \) of type \( \texttt{node} \), the fields have the following meaning:
\begin{itemize}
	\item \textbf{n.id}: The unique identifier of node \( n \)   
	\item \textbf{n.fn}: The function symbol (or variable name) represented by this node 
	\item \textbf{n.args}: The list of identifiers of the argument nodes (empty for variables and constants)
	\item \textbf{n.find}: The identifier of the representative node of the equivalence class to which \( n \) belongs
	\begin{itemize}
		\item \textit{Initialization}: \texttt{n.find = n.id} (each node starts in its own equivalence class)
	\end{itemize}
	\item \textbf{n.ccpar}: The set of identifiers of the parent nodes of \( n \) (nodes that have \( n \) as an argument) and all nodes congruent to \( n \)
\end{itemize}	
\end{definition}
This data structure supports the union-find operations needed for the congruence closure algorithm, where \texttt{find}
implements the path to the representative of each equivalence class, and \texttt{ccpar} tracks congruence relationships
for efficient propagation.
\subsection{Basic Operations}
We now define the basic operations on the DAG structure.
\subsubsection{The NODE Function}
The function \texttt{NODE} retrives a node given its identifier:
\[
  \texttt{NODE}: \texttt{Id} \rightarrow \texttt{Node}
\]
\[
  \texttt{NODE}(i) = n \quad \text{ such that } \quad n.\texttt{id} = i
\]
\subsubsection{The FIND Operation}
The \texttt{FIND} function takes an identifier and returns the identifier of the representative of the equivalence 
class to which the node belongs:
\[
  \texttt{FIND} : \texttt{Id} \rightarrow \texttt{Id}
\]
\begin{lstlisting}[style=ocamlpseudo]
let rec FIND i = 
	let n = NODE i in 
		if n.find = i then i 
		else FIND n.find
\end{lstlisting}
This recursive function follows the \texttt{find} pointers until it reaches a node that is its own representative
(i.e., \( n \).\texttt{find} = \( n \).\texttt{id}).
\subsubsection{The UNION Operation}
The \texttt{UNION} function merges two equivalence classes:
\[
  \texttt{UNION} : \texttt{Id} \times \texttt{Id} \rightarrow \texttt{void}
\]
\begin{lstlisting}[style=ocamlpseudo]
let UNION i_1 i_2 = 
	let n_1 = NODE (FIND i_1) in 
	let n_2 = NODE (FIND i_2) in 
	n_1.find <- n_2.find; 
	n_2.ccpar <- n_2.ccpar U n_1.ccpar;
	n_1.ccpar <- empty_set
\end{lstlisting}
The \texttt{UNION} operation performs the following steps:
\begin{enumerate}
	\item Find the representatives \( n_1 \) and \( n_2 \) of the two equivalence classes 
	\item Make \( n_1 \) point to \( n_2 \) (merging the classes)
	\item Transfer the \texttt{ccpar} set from \( n_1 \) to \( n_2 \)   
	\item Clear the \texttt{ccpar} set of \( n_1 \)
\end{enumerate}
\textit{Note}. During execution, \( n \).\texttt{ccpar} \( \neq \varnothing \) if and only if \( n \) is a representative 
(i.e., \( n \).\texttt{find} = \( n \).\texttt{id}). This invariant ensures that only representative nodes maintain the parent and 
congruence information.
\subsubsection{The CCPAR Function}
The \texttt{CCPAR} function return the \texttt{ccpar} set of the representative of a given node:
\[
  \texttt{CCPAR}: \texttt{Id} \rightarrow \texttt{Id set}
\]
\begin{lstlisting}[style=ocamlpseudo]
let CCPAR i = (NODE (FIND i)).ccpar	
\end{lstlisting}
This function first finds representative of node \( i \), then returns its \texttt{ccpar} set.
\subsubsection{The CONGRUENT Function}
The \texttt{CONGRUENT} function checks whether two nodes are congruent (i.e., they have the same function symbol 
and their corresponding arguments are in the same equivalence classes):
\[
  \texttt{CONGRUENT}: \texttt{Id} \times \texttt{Id} \rightarrow \texttt{bool}
\]
\begin{lstlisting}[style=ocamlpseudo]
let CONGRUENT i_1 i_2 = 
	let n_1 = NODE i_1 in 
	let n_2 = NODE i_2 in 
	n_1.fn = n_2.fn &&
	|n_1.args| = |n_2.args| &&
	forall i in {1, ..., |n_1.args|}
		FIND n_1.args[i] = FIND n_2.args[i]
\end{lstlisting}
Two nodes are congruent if:
\begin{enumerate}
	\item They have the same function symbol \( n_1.\texttt{fn} = n_2.\texttt{fn} \)   
	\item They have the same number of arguments \( (\;|\;n_1.\texttt{args}\;|\; = \;|\;n_2.\texttt{args}\;|\;) \)   
	\item Their corresponding arguments are in the same equivalence classes
\end{enumerate}
\subsubsection{The MERGE Function}
\begin{definition}{MERGE Operation}{MERGE Operation}
The \texttt{MERGE} function merges two equivalence classes and recursibely propagates congruence:
\[
  \texttt{MERGE}: \texttt{Id} \times \texttt{Id} \rightarrow \texttt{void}
\]
\begin{lstlisting}[style=ocamlpseudo]
let rec MERGE i_1 i_2 = 
	if FIND i_1 =/= FIND i_2 then 
		begin
			let P_1 = CCPAR i_1 in
			let P_2 = CCPAR i_2 in 
			UNION i_1 i_2;
			foreach (t_1, t_2) in P_1 x P_2 do 
				if FIND t_1 =/= FIND t_2 && CONGRUENT t_1 t_2
				then MERGE t_1 t_2
			done
		end
\end{lstlisting}
The \texttt{MERGE} operation works as follows:
\begin{enumerate}
	\item Check if \( i_1 \) and \( i_2 \) are already in the same equivalence class; if so, do nothing 
	\item Save the \texttt{ccpar} sets \( P_1 \) and \( P_2 \) of both nodes 
	\item Perform \texttt{UNION} to merge the equivalence classes 
	\item For each pair \( (t_1,t_2) \) in the Cartesian product \( P_1 \times P_2 \):
	\begin{itemize}
		\item If \( t_1 \) and \( t_2 \) are not already equivalent and are congruent 
		\item Recursively merge them with \texttt{MERGE}
	\end{itemize}
\end{enumerate}
\end{definition}
This recursive propagation ensures that when two nodes become equivalent, all pairs of congruent parent nodes are also merged, maintaining the 
congruence closure property
\subsection{The Complete Congruence Closure Algorithm}
We can now describe the complete congruence closure algorithm using the DAG-based implementation
\subsubsection{Algorithm}
\begin{theorem}{Complete Congruence Closure Algorithm (DAG-based)}{Complete Congruence Closure Algorithm (DAG-based)}
Given a formula:
\[
  F = \left\{ s_1 = t_1, \ldots, s_n = t_n \right\} \cup \left\{ s_{n + 1} \neq t_{n + 1}, \ldots, s_{n + m} \neq t_{n + m} \right\}
\]
The algorithm proceeds as follows:
\begin{algorithm}[H]
	\caption{Complete Congruence Closure Algorithm (DAG-based)}
	\begin{algorithmic}[2]
		\Require Formula $F = F^+ \cup F^-$ where $F^+ = \left\{ s_1 = t_1, \ldots, s_n = t_n \right\}$ and
		$F^- = \left\{ s_{n + 1} \neq t_{n + 1}, \ldots, s_{n + m} \neq t_{n + m} \right\}$
		\State Construct the DAG for \( F \)
		\For{$i = 1$ to $n$ \textbf{do}}
			\State \texttt{MERGE}($s_i, t_i$)
		\EndFor
		\For{$i = n + 1$ to $n + m$ \textbf{do}}
			\If{\texttt{FIND}($s_1$) = \texttt{FIND}($t_i$) \textbf{then}}
				\State \Return UNSATISFIABLE 
			\EndIf
		\EndFor
		\State \Return SATISFIABLE
	\end{algorithmic}
\end{algorithm}
\end{theorem}
\textbf{Steps}:
\begin{enumerate}
	\item \textbf{Construct the DAG}: Build the DAG representation of all terms in \( F \)   
	\item \textbf{Process equalities}: For each equality \( s_i = t_i \) in \( F^+ \), call \texttt{MERGE}($s_i, t_i$) to merge the equivalence classes and propagate congruence 
	\item \textbf{Check disequalities}: For each disequality $s_i \neq t_i$ in $F^-$, check if $s_i$ and $t_i$, are in the same equivalence class (i.e., \texttt{FIND}($s_i$) = \texttt{FIND}($t_i$))
	\begin{itemize}
		\item If yes, return UNSATISFIABLE
	\end{itemize}
	\item \textbf{Return result}: If no conflicts found, return SATISFIABLE
\end{enumerate}
\subsubsection{Complexity}
\begin{definition}{Complexity Analysis}{Complexity Analysis}
Let \( n \) be the number of nodes in the DAG. The complexity of the congruence closure algorithm is \( O(n^2) \) in the worst case, 
where the quadratic factor comes from the potential number of congruence propagations that may occur during the \texttt{MERGE} 
operations.
\end{definition}
\section{Worked Examples of Congruence Closure}
In this section, we present detailed worked examples demonstrating the execution of the congruence closure algorithm 
on concrete formulas. These examples illustrate the DAG construction, the initialization of node fields, and the step-by-step exectuion of 
the \texttt{MERGE} operations.
\subsection{Example 1: Simple Commutativity}
\begin{example}{Congruence Closure with Commutativity}{Congruence Closure with Commutativity}
Consider the formula without quantifiers:
\[
  F = \left\{ f(x,y) = f(y,x) \right\} \cup \left\{ f(a,y) = f(y,a) \right\}
\]
where \( a \) is a constant symbol.
\end{example}
\textbf{Step 1: Identify the set of subterms}
\vspace{1em}
\noindent
\newline
The set of all subterms appearing in \( F \) is:
\[
  S_F = \left\{ x,y,a,f(x,y),f(y,x),f(a,y)f(y,a) \right\}
\]
\textbf{Step 2: Construct the DAG}
\vspace{1em}
\noindent 
\newline
We construct a DAG where each node represents a unique subterm. Each node has the following fields:
\begin{itemize}
	\item \textbf{id}: A unique integer identifier 
	\item \textbf{fn}: The function symbol (or variable/constant name) as a string 
	\item \textbf{args}: List of identifiers of arugment nodes (empty for variables/constants)
	\item \textbf{find}: Initially set to the node's own id 
	\item \textbf{ccpar}: Set of parent node identifiers (initially contains all nodes that have this node as an argument)
\end{itemize}
The DAG structure ca ben visualized as:
\[
\begin{array}{cccc}
	f_3 & f_4 & f_5 & f_6 \\
	\textcolor{blue}{\downarrow} & \textcolor{blue}{\downarrow} & \textcolor{blue}{\downarrow} & \textcolor{blue}{\downarrow} \\
	(x_0, y_1) & (y_1, x_0) & (a_2, y_1) & (y_1, a_2) 
\end{array}
\]
\textbf{Step 3: Initialize node fields}
\begin{definition}{Initial DAG Node Configuration}{Initial DAG Node Configuration}
\texttt{Node} $f_3$: $\quad$ \texttt{id} = 3, \texttt{fn} = "f", \texttt{args} = [0, 1], \texttt{find} = 3, \texttt{ccpar} = \( \left\{\right\} \)
\vspace{1em}
\noindent
\newline
\texttt{Node} $x_0$: $\quad$ \texttt{id} = 0, \texttt{fn} = "x", \texttt{args} = [], \texttt{find} = 0, \texttt{ccpar} = \( \left\{3, 4\right\} \)
\vspace{1em}
\noindent
\newline
\texttt{Node} $f_4$: $\quad$ \texttt{id} = 4, \texttt{fn} = "f", \texttt{args} = [1, 0], \texttt{find} = 4, \texttt{ccpar} = \( \left\{\right\} \)
\vspace{1em}
\noindent
\newline
\texttt{Node} $y_1$: $\quad$ \texttt{id} = 1, \texttt{fn} = "y", \texttt{args} = [], \texttt{find} = 1, \texttt{ccpar} = \( \left\{3, 4, 5, 6\right\} \)
\vspace{1em}
\noindent
\newline
\texttt{Node} $f_5$: $\quad$ \texttt{id} = 5, \texttt{fn} = "f", \texttt{args} = [2, 1], \texttt{find} = 5, \texttt{ccpar} = \( \left\{\right\} \)
\vspace{1em}
\noindent
\newline
\texttt{Node} $a_2$: $\quad$ \texttt{id} = 2, \texttt{fn} = "a", \texttt{args} = [], \texttt{find} = 2, \texttt{ccpar} = \( \left\{5, 6\right\} \)
\vspace{1em}
\noindent
\newline
\texttt{Node} $f_6$: $\quad$ \texttt{id} = 6, \texttt{fn} = "f", \texttt{args} = [1, 2], \texttt{find} = 6, \texttt{ccpar} = \( \left\{\right\} \)
\end{definition}
\textbf{Key observation about initialization}:
\begin{itemize}
	\item Each node's \texttt{find} intially points to itself 
	\item The \texttt{ccpar} field of each leaf node (variables/constants) contains the ids of all funcion nodes that have it as an argument 
	\item Function nodes initially have empty \texttt{ccpar} sets
\end{itemize}
\textbf{Step 4: Process the equality} \( f(x,y) = f(y,x) \)   
\vspace{1em}
\noindent
\newline
We exectue \texttt{MERGE}(3,4) corresponding to the equality \( f(x,y) = f(y,x) \):
\begin{enumerate}
	\item Check if \texttt{FIND}(3) \( \neq \) \texttt{FIND}(4): YES (they are 3 and 4 respectively)
	\item Save parent sets: \( P_1 = \texttt{CCPAR}(3) = \varnothing, P_2 = \texttt{CCPAR}(4) = \varnothing \)   
	\item Execute \texttt{UNION}(3, 4):
	\begin{itemize}
		\item Set node 4's \texttt{find} field to 3 
		\item Merge \texttt{ccpar} sets (both empty in this case)
	\end{itemize}
	\item Check Cartesian products \( P_1 \times P_2 = \varnothing \times \varnothing = \varnothing \)   
	\item No further merges needed
\end{enumerate}
After this operation, nodes \( f_3 \) and \( f_4 \) are in the same equivalence class.
\vspace{1em}
\noindent
\newline
\textbf{Step 5: Check the disequality (if any)}
\vspace{1em}
\noindent
\newline
In this example, we only have equalities. The formula \( f(a,y) = f(y,a) \) represents another equality that could 
be processed similarly. Since \( f(a,y) \) and \( f(y,a) \) (nodes 5 and 6) remain in distinct equivalence classes after 
processing the first equality, the formula is \textbf{SATISFIABLE} - there is no contradiction.
\subsection{Example 2: Cyclic Function Application with Disequality}
\begin{example}{Detecting Unsatisfiability through Congruence Closure}{Detecting Unsatisfiability through Congruence Closure}
Consider the formula:
\[
  F = \left\{f^3(a) = f^5(a) \right\} \cup \left\{f(a) \neq a \right\}
\]
where we use the notation \( f^n(a) \) to denote \( n \) applications of function \( f \) to constant \( a \). 
Explicity:
\begin{itemize}
	\item \( f^3(a) = f(f(f(a))) \)    
	\item \( f^5(a) = f(f(f(f(f(a))))) \)
\end{itemize}
\end{example}
\textbf{Step 1: Identify the set of subterms}
\vspace{1em}
\noindent
\newline
The set of all subterms is:
\[
  S_F = \left\{a,f(a),f^2(a),f^3(a),f^4(a),f^5(a)\right\}
\]
\textbf{Step 3: Construct the DAG}
\vspace{1em}
\noindent
\newline
We build a chain-like DAG where each node represents successive applications of \( f \):
\[
  f^5(a) \rightarrow f^4(a) \rightarrow f^3(a) \rightarrow f^2(a) \rightarrow f(a) \rightarrow a 
\]
\textbf{Step 3: Initialize node fields}
\begin{definition}{Initial DAG Configuration}{Initial DAG Configuration}
\texttt{Node} 5: \texttt{id} = 5, \texttt{fn} = "f", \texttt{args} = [4], \texttt{find} = 5, \texttt{ccpar} = \( \left\{\right\} \)   
\newline 
\texttt{Node} 4: \texttt{id} = 4, \texttt{fn} = "f", \texttt{args} = [3], \texttt{find} = 4, \texttt{ccpar} = \( \left\{5\right\} \)   
\newline 
\texttt{Node} 3: \texttt{id} = 3, \texttt{fn} = "f", \texttt{args} = [2], \texttt{find} = 3, \texttt{ccpar} = \( \left\{4\right\} \)   
\newline 
\texttt{Node} 2: \texttt{id} = 2, \texttt{fn} = "f", \texttt{args} = [1], \texttt{find} = 2, \texttt{ccpar} = \( \left\{3\right\} \)   
\newline 
\texttt{Node} 1: \texttt{id} = 1, \texttt{fn} = "f", \texttt{args} = [0], \texttt{find} = 1, \texttt{ccpar} = \( \left\{2\right\} \)   
\newline 
\texttt{Node} 0: \texttt{id} = 0, \texttt{fn} = "a", \texttt{args} = [], \texttt{find} = 0, \texttt{ccpar} = \( \left\{1\right\} \)   
\end{definition}
\textbf{Step 4: Process the equality} \( f^3(a) = f^5(a) \)   
\vspace{1em}
\noindent
\newline
The equality \( f^3(a) = f^5(a) \) implies that after three applications of \( f \), we get the same result as after 
five applications. This creates a cycle in the equivalence structure.
\vspace{1em}
\noindent
\newline
We execute \texttt{MERGE}(3,5). However, the congruence closure algorithm will propagate this equality through the structure,
ultimately establishing relationships between multiple nodes.
\vspace{1em}
\noindent
\newline
\textbf{Logical Implications of the equality}:
\vspace{1em}
\noindent
\newline
From \( f^3(a) = f^5(a) \), by applying the congruence rule repeatedly, we can derive:
\begin{center}
	\begin{align*}
		& f^3(a) = f^5(a) \\
		& f^4(a) = f^6(a) = f(f^5(a)) = f(f^3(a)) \\
		& f^2(a) = f^4(a) \text{ (by applying \( f^{-1 } \) conceptually)}\\
		& f(a) = f^3(a) \\
		& a = f^2(a) 
	\end{align*}
\end{center}
More precisely, the algorithm establishes these equivalences through congruence propagation.
\vspace{1em}
\noindent
\newline
\textbf{Step 5: Detailed execution trace}
\vspace{1em}
\noindent
\newline
We now trace the execution of \texttt{MERGE}(3,5) and observe how congruence propagates:
\begin{theorem}{Execution Trace}{Execution Trace}
\textbf{Call: MERGE(3,5)}
\vspace{1em}
\noindent
\newline
Since \( f^3(a) = f^5(a) \), we need to merge nodes 3 and 5. 
\begin{enumerate}
	\item \texttt{FIND}(3) = 3, \texttt{FIND}(5) = 5 (different, so proceed)
	\item \( P_1 = \texttt{CCPAR}(3) = \left\{4\right\}, P_2 = \texttt{CCPAR}(5) = \varnothing \)   
	\item \texttt{UNION}(3,5): merge the equivalence classes 
	\item Check \( P_1 \times P_2 = \left\{4\right\} \times \varnothing = \varnothing \) (no propagation yet)
\end{enumerate}
However, the equality \( f^3(a) = f^5(a) \) implies \( f^2(a) = f^4(a) \) by the congruence property.
\vspace{1em}
\noindent
\newline
This triggers further merges.
\vspace{1em}
\noindent
\newline
\textbf{Call: MERGE(3, 0)} (establishing \( f^3(a) = a \))
\begin{enumerate}
	\item \( P_1 = \texttt{CCPAR}(3) = \left\{4\right\}, P_2 = \texttt{CCPAR}(0) = \left\{1\right\} \)    
	\item \texttt{UNION}(3, 0)
	\item Check \( P_1 \times P_2 = \left\{4\right\} \times \left\{1\right\} = \left\{(4,1)\right\} \)   
	\item \texttt{CONGRUENT}(4,1)?
	\begin{itemize}
		\item Same symbol: YES (\( f = f \))
		\item Same arity: YES (both unary)
		\item Arguments equivalent: \texttt{FIND}(3) = \texttt{FIND}(0) after union: YES
	\end{itemize}
	\item Result: TRUE \( \Rightarrow \) call \texttt{MERGE}(4,1)
\end{enumerate}
\vspace{1em}
\noindent
\newline
\textbf{Call: MERGE(4, 1)} (establishing \( f^4(a) = f(a) \))
\begin{enumerate}
	\item \( P_1 = \texttt{CCPAR}(4) = \left\{5\right\}, P_2 = \texttt{CCPAR}(1) = \left\{2\right\} \)    
	\item \texttt{UNION}(4, 1)
	\item Check \( P_1 \times P_2 = \left\{5\right\} \times \left\{2\right\} = \left\{(5,2)\right\} \)   
	\item \texttt{CONGRUENT}(5,2)?
	\begin{itemize}
		\item Same symbol: YES
		\item Same arity: YES 
		\item Arguments equivalent: \texttt{FIND}(4) = \texttt{FIND}(1): YES
	\end{itemize}
	\item Result: TRUE \( \Rightarrow \) call \texttt{MERGE}(5,2)
\end{enumerate}
\vspace{1em}
\noindent
\newline
\textbf{Call: MERGE(5, 2)} (establishing \( f^5(a) = f^2(a) \))
\begin{enumerate}
	\item \( P_1 = \texttt{CCPAR}(5) = \varnothing, P_2 = \texttt{CCPAR}(2) = \left\{3\right\} \)    
	\item \texttt{UNION}(5, 2)
	\item Check \( P_1 \times P_2 = \varnothing \times \left\{3\right\} = \varnothing \)   
	\item No further propagation
\end{enumerate}
The congruence closure process continues, eventualy establishing that all nodes \( \left\{0,1,2,3,4,5\right\} \) are 
in the same equivalence class, meaning:
\[
  a = f(a) = f^2(a) = f^3(a) = f^4(a) = f^5(a)
\]
\end{theorem}
\textbf{Step 6: Check the disequality} \( f(a) \neq a \)   
\vspace{1em}
\noindent
\newline
After processing all equalities through congruence closure, we check the disequality constraint:
\begin{itemize}
	\item We have \( f(a) \neq a \) in \( F^- \)   
	\item Check: \texttt{FIND}(1) = \texttt{FIND}(0)?
	\item After congruence closure: YES (they are in the same equivalence class)
	\item \textbf{Conclusion}: The disequality is violated!
\end{itemize}
\textbf{Result}: The formula is \textbf{UNSATISFIABLE}. The quality \( f^3(a) = f^5(a) \) forces a cycle that 
ultimately implies \( f(a) = a \), which contradicts the disequality constraint \( f(a) \neq a \).
\section{Complexity Improvements and Optimiazions}
The basic congruence closure algorithm presented earlier has complexity \( O(n^2) \) for \( n \) nodes in 
the DAG. However, several optimizations have been developed to improve the practical and theoretical performance 
of the algorithm.
\subsection{Hisotical Development}
\subsubsection{Nelson-Oppen Algorithm (1980)}
The original congruence closure algorithm by Nelson and Oppen (1980) operates on a graph \( G = (V,E) \) where:
\begin{itemize}
	\item \( \;|\; V \;|\; = n \) (number of nodes/vertices)
	\item \( \;|\; E \;|\; = e \) (number of edges)
\end{itemize}
\begin{definition}{Nelson-Oppen Complexity}{Nelson-Oppen Complexity}
The Nelson-Oppen algorithm has complexity \( O(n^2) \) for \( O(n) \) calls to \texttt{MERGE}
\end{definition}
This quadratic complexity in the number of edges can be prohibitive for large formulas with many equalities.
\subsubsection{Downey-Sethi-Tarjan Improvements (1980-1982)}
Downey, Sethi and Tarjan developed several optimiazions that significantly improved the complexity of congruence 
closure Algorithms
\begin{definition}{Improved Complexity}{Improved Complexity}
The Downey-Sethi-Tarjan optimizations reduce the complexity to \( O(e log e) \) for \( O(n) \) calls to \texttt{MERGE}
\end{definition}
This represent a substantial improvement, especially for sparse graphs where \( e \) is much smaller than \( n^2 \).
\subsection{Key Optimization}
The improvements introduced by Downey, Sethi and Tarjan focus on two main aspects of the algorithm:
\subsubsection{Optimiazion 1: Avoiding Recursion in FIND}
\textbf{Original recursive implementation}:
\begin{lstlisting}[style=ocamlpseudo]
let rec FIND i = 
	let n = NODE i in 
		if n.find = i then i 
		else FIND n.find
\end{lstlisting}
\textbf{Optimized non-recursive implmentation}
\begin{lstlisting}[style=ocamlpseudo]
let FIND i = (NODE i).find
\end{lstlisting}
\textit{Note}. This optimization is correct only if the \texttt{UNION} operation is modified appropriately. When 
node \( i_1 \) becomes the representative of the merged equivalence class, the \texttt{find} field of \textbf{all nodes}
in \( i_2 \)'s class must be updated to point directly to \( i_1 \).
\vspace{1em}
\noindent
\newline
This eliminates the need for path trasversal during \texttt{FIND} operations, reducing the cost from \( O(h) \) (where
\( h \) is the height of the union-find tree) to \( O(1) \).
\subsubsection{Optimiazion 2: Union by Size Heuristic}
When mergin two equivalence classes via \texttt{UNION}($i_1,i_2$), we must choose which representative becomes
the representative of the merged class. Two effective heuristic are:
\begin{definition}{Union Heuristic}{Union Heuristic}
\textbf{Heuristic 1: Union by Equivalence Class Size}
\vspace{1em}
\noindent
\newline
Choose as the representative of the new class the representative of the \textbf{larger equivalence class:}
\begin{itemize}
	\item Compare \( \;|\;[i_1]\;|\; \text{ and } \;|\;[i_2]\;|\; \) (sizes of the equivalence classes)
	\item Make the representative of the larger class the new representative
\end{itemize}
\textbf{Heuristic 2: Union by CCPAR Size}
\vspace{1em}
\noindent
\newline
Choose as the representative the node whose \texttt{ccpar} field has \textbf{more members}:
\begin{itemize}
	\item Compare \( \;|\;i_1.\texttt{ccpar}\;|\; \text{ and } \;|\;i_2.\texttt{ccpar}\;|\; \)
	\item Make the representative with the larger \texttt{ccpar} set the new representative
\end{itemize}
\end{definition}
\textbf{Rationale}: These heuristics ensure that the union-find tree remains balanced, preventing degenerate cases where 
the tree becomes a long chain. By always attaching the samller structure to the larger one, we maintain logarithmic depth in the 
union-find structure.
\subsection{Implementation Note}
The \texttt{CCPAR} function must retrive the \texttt{ccpar} set of the representative node:
\begin{lstlisting}[style=ocamlpseudo]
let CCPAR i = (NODE (FIND i)).ccpar
\end{lstlisting}
This ensure that we always access the \texttt{ccpar} information from the current representative of the equivalence 
class, which is essential for correctness after multiple \texttt{UNION} operations.
\subsection{Practical Impact}
These optimiazions have significant practical impact:
\begin{itemize}
	\item \textbf{Reduced time complexity}: From \( O(e^2) \) to \( O(e log e) \)    
	\item \textbf{Better cache locality}: Non-recursive \texttt{FIND} reduces function call overhead
	\item \textbf{Balanced structures}: Union heuristics prevent worst-case tree depths 
	\item \textbf{Scalability}: Enables congruence closure on much larger formulas 
\end{itemize} 
These improvements make congruence closure practical for real-world applications in automated theorem proving,
program verification, and satisfiability modulo theories (SMT) solvers.
